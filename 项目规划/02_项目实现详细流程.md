# 智启课源项目实现详细流程

版本 1.0　编制日期 2026年9月4日　配套文件 01_项目计划书和03_AI执行任务包

## 1 执行原则和技术边界

本手册按“独立前端加精简后端”路线编写。所有 `/api/v1` 接口、数据表、开发目录、任务编号和子页面参数都是新项目设计，不能直接当成 DeepTutor 已提供的接口。若选择 DeepTutor 二次开发，应改为阅读固定版本的真实契约并使用其服务，不执行本手册的自建后台部分。

开始时先交付 Mock 前端；之后逐个替换服务适配器接入真实 API。页面组件不直接调用模型供应商，也不自行读写数据库。公共类型、设计变量和 API 只有一套，所有参与的 AI 都读取同一版本。

每个阶段遵循同一流程：读取输入资料，列出修改文件，完成实现，执行相关检查，提供截图或真实请求证据，更新交接记录，保存一个可恢复的版本。发现需求冲突时记录具体冲突，不擅自改掉已经通过验收的全局约定。

## 2 第一步 固定参考版本和页面基线

输入：DeepTutor 仓库、提交 `e5f2d38c393497a57fda13209be55067c1740ca7`、本项目计划和首个演示资料。输出：参考来源清单、截图集、路由清单和依赖清单。

在独立参考目录检出该版本；不要把整个参考项目的依赖、数据目录和密钥拷入新项目。下面为后续执行者使用的 PowerShell 示例，本次规划没有运行这些克隆和安装命令。

```powershell
Set-Location 'F:\智启课源'
New-Item -ItemType Directory -Force 'references'
git clone --depth 1 --branch v1.6.4 https://github.com/HKUDS/DeepTutor.git references/DeepTutor
git -C references/DeepTutor rev-parse HEAD
```

核对输出 SHA 与上方一致。阅读 `web/package.json`、`web/app/globals.css`、`web/components/sidebar/nav-entries.ts`、`web/components/sidebar/SidebarShell.tsx`、`web/app`、`web/features` 和 `web/contracts`。先记录使用哪些组件和交互，再决定是否复用源码。

截图至少覆盖首页、长会话、知识库列表与详情、学习空间、笔记、题库、阅读、书本、学习路径、写作、伙伴、智能体、记忆、设置。每个核心页面保存默认态和一个展开态。统一主题、语言、缩放和数据，记录来源 URL、版本和拍摄视口。

本次已核对的[官网首页截图](https://deeptutor.info/screenshots/OVERVIEW.png)可作为首页视觉起点；未取得的截图明确登记为待补，不用 AI 猜测图代替参考。固定版本源码是尺寸和路由的最终核查依据。

通过条件：每个计划页面都有对应来源或明确标记为本项目新增；原项目版本及本项目设计决策分开记录。

## 3 第二步 建立设计变量与公共布局

### 3.1 视觉基线

首版以 DeepTutor 的白色默认主题为准。以下颜色及侧栏尺寸取自固定提交，其余字号、间距和分栏值是本项目实施起点，需要用真实截图微调。[主题源码](https://github.com/HKUDS/DeepTutor/blob/e5f2d38c393497a57fda13209be55067c1740ca7/web/app/globals.css) [侧栏源码](https://github.com/HKUDS/DeepTutor/blob/e5f2d38c393497a57fda13209be55067c1740ca7/web/components/sidebar/SidebarShell.tsx)

| 项目 | 初始值 | 使用位置 |
| --- | --- | --- |

| 侧栏与次级背景 | #F7F7F7 | 左侧导航、次级区域 |
| 正文 | #0D0D0D | 标题和主要文字 |
| 次级文字 | #6E6E6E | 提示、辅助信息 |

将变量放在一个主题文件中，用语义名称引用。不要在每个页面散落颜色常量。深色主题放到公共布局稳定之后实施，所有页面共用主题切换；初期不必同时实现原版所有主题。

### 3.2 页面外壳

桌面外壳由左侧导航、主工作区和可选右面板组成。侧栏上方放项目文字标识和折叠按钮，中部放功能入口和最近会话，下方固定记忆、知识中心及设置。主区域顶部放页面标题和当前页面操作。正文独立滚动，输入框保持可见，避免全页滚动与消息区滚动互相干扰。

聊天正文先以 800px 左右最大宽度居中实现，阅读和编辑页可使用全部剩余宽度。右侧活动面板初始约 360px，可收起；视口不足时改用抽屉。以上正文和面板宽度是项目建议，不是对参考图的精确量取。

响应式约定：1280px 及以上可展示三栏；768 至 1279px 优先保留内容与侧栏，辅助面板覆盖式展开；小于 768px 使用单栏和抽屉导航。阅读页的正文与问答在手机上使用标签切换。以 `100dvh` 适配移动地址栏，并实际测试软键盘出现后的输入框位置。

### 3.3 公共组件

先完成 AppShell、Sidebar、PageHeader、Button、IconButton、Input、Select、Dialog、Drawer、Tabs、Card、DropdownMenu、Tooltip、Toast、EmptyState、LoadingState、ErrorState、ConfirmDialog，再实现 Composer、MarkdownRenderer、CitationChip、FileDropzone、TaskStatus、MessageList。

给图标按钮提供可读名称，弹窗打开后焦点进入弹窗，关闭后回到触发按钮。按钮的不可用状态解释原因；状态不能只靠颜色区分。表格与代码块在自己的区域横向滚动，不让整个页面超过手机宽度。动效尊重系统减少动画的设置。

通过条件：同一组件的外观和行为一致，侧栏当前项与 URL 一致，刷新后主题和侧栏偏好能恢复，直接打开深层链接可用，键盘能完成基础操作。

## 4 第三步 按页面实现交互

### 4.1 首页与聊天

默认态：顶部显示“新对话”；中间为问候和大输入框，下方展示三条学习建议。输入框包含模式、附件、知识库、角色和模型入口。V0.2 中模型列表使用固定演示数据，不能暗示已经连接真实供应商。

操作流程：用户输入后发送，创建会话并进入 `/chat/[sessionId]`；消息从等待变为输出中，再进入完成或失败。用户向上滚动查看历史时，新增文字不能强制把视口拉回底部；提供“回到最新”按钮。支持停止、复制、保存到笔记、重新生成和 Markdown 导出。

活动面板只展示实际事件、调用摘要、引用和附件，不伪造模型内部思考过程。点击引用打开资料定位。建议问题点击后默认填入输入框，由用户发送。中文输入法组合输入期间，Enter 不得误发；桌面约定 Enter 发送，Shift+Enter 换行。

需要演示的状态：空会话、长会话、生成中、已停止、失败、重试、网络断开、模型未配置、知识库未就绪。真实版检查刷新恢复、切换会话后后台生成状态、重复点击发送和取消结果。

### 4.2 知识中心与文件详情

列表包含知识库名称、说明、文件数量、索引状态和更新时间，支持搜索、创建与删除。详情页包含文件列表、添加文件、检索设置和预览区。新项目首期只提供一种检索引擎，避免展示无法使用的配置。

上传步骤：选择文件，显示名称、大小和校验结果，上传完成后进入后台解析与索引；页面分别显示上传进度和处理状态。首版建议 PDF、TXT、Markdown，每个文件上限先定为 20MB；这是本项目限制，不是 DeepTutor 的原有限制。

单文件状态采用 queued、parsing、indexing、ready、failed、cancelled。资料库状态由文件汇总，允许“部分可用”。解析失败展示原因、重试和移除；删除单个失败文件不需要删除整个资料库。只有已就绪版本可参与检索。

重建索引写入新版本，验证后切换活动版本，旧版本保留用于回退。嵌入模型或维度变化必须新建索引，不能混存。原项目也采用版本化索引和文件级管理，可参考其页面组织。[知识中心说明](https://docs.deeptutor.info/explore/knowledge/)

### 4.3 学习空间与历史

学习空间以资源卡片组织会话、笔记和题库，后续添加角色和扩展能力。数量在真实版由服务端返回，不能写死。历史页支持按关键词、归档状态和会话模式筛选，支持重命名、归档、恢复和打开。

删除会话前确认；归档不等于删除。空状态给出“开始对话”等可执行入口。重开会话要恢复选定知识库、可用模型偏好和消息，而不只是恢复一个标题。

### 4.4 笔记本

左侧显示笔记本和搜索，右侧显示记录列表或编辑内容。每条记录保留标题、正文、来源类型、来源 ID、创建时间和更新时间。来源可以是某条回答、某道题或某页资料。

编辑器首版用 Markdown，不同时开发复杂富文本。自动保存采用短暂防抖，必须显示“保存中、已保存、保存失败”。服务端使用版本号检查冲突，避免两个标签页互相覆盖。导出采用 Markdown；删除来源后保留笔记正文及“来源已不可访问”提示。

### 4.5 题库与练习

题库列表包含题型、知识点、难度、答题状态和收藏。首版实现单选、多选和判断；简答题可以展示参考答案和 AI 建议，但没有可靠评分规则前不纳入确定性成绩。

生成练习先选择来源、题数、类型和难度，后端校验模型返回结构。用户提交前，浏览器只拿到题目和选项，不拿到正确答案。提交后服务端完成评分，返回得分、正确选项、解析和来源。

多选题首版使用严格集合相等评分并明确提示；同一次提交使用幂等键避免重复记分。作答结果和题目版本同时保存，生成同类新题时不覆盖既有作答。错题筛选依赖实际答题记录，不能由前端随意设置。

### 4.6 沉浸阅读

列表页选择资料，阅读页左侧显示 PDF 或文本，右侧显示围绕该资料的会话。顶部提供目录、页码、缩放、书签，选择一段文字后出现“解释所选内容”的操作。

PDF 使用物理页码；TXT 和 Markdown 使用段落或章节定位，不能编造页码。引用保存 doc_id、version、locator 和可核验的原文片段。切换或重新上传资料后检查定位版本，旧引用打不开时明确说明。

首版完成页码或段落跳转和书签，精确跨行高亮后置。扫描 PDF 无文本时明确提示暂不支持，需要 OCR；不要打开空页面后宣称资料已可问答。原版沉浸阅读与多文档知识库是不同工作方式，本项目也分别处理。[阅读说明](https://docs.deeptutor.info/explore/reading/)

### 4.7 书本与学习路径

书本页：书架卡片，创建向导，来源选择，可编辑章节大纲，章节阅读，生成状态。V0.2 用固定章节展示操作；真实版先生成一个章节，检查引用和成本后再支持整本。后台任务必须可取消、重试，并记录生成版本。

学习路径页：目标卡片、目标输入、学习材料选择、大纲编辑、知识节点和进度。区分未开始、学习中、已完成、待复习。V0.2 的进度来自模拟题目；真实版定义掌握规则后再解锁下一节点，不能把“看过页面”自动算作掌握。参考产品以目标、材料和大纲组织创建流程。[学习路径说明](https://docs.deeptutor.info/explore/mastery-path/)

### 4.8 写作 伙伴 智能体和记忆

协同写作采用文档列表、Markdown 编辑区和 AI 建议区。选段改写先展示建议差异，由用户接受或拒绝；保存历史版本以便撤回。不要直接覆盖全文。V0.2 用固定建议模拟。

伙伴页采用角色卡片、创建或编辑表单和绑定会话。首个真实版本仅实现站内角色提示和独立会话；外部聊天平台接入作为新任务。我的智能体页展示连接状态和能力，演示模式用清晰的测试记录；没有真实适配器时不显示“已连接”。

记忆页先管理用户明确保存的学习目标、偏好和弱项，每条记录带来源，支持编辑和删除。自动从所有对话提炼长期记忆在后续设计中增加，先处理删除同步、冲突和用户可控性。

### 4.9 设置 登录和个人资料

设置页使用可搜索分组导航和表单面板，覆盖模型、外观、上传限制和账户。模型配置记录供应商、服务端地址、模型 ID、用途和能力；保存与测试连接分开，测试真实发起最小请求并返回脱敏错误。

密钥只通过受保护接口提交到服务端，读取时返回“已配置”或掩码；不在 localStorage、网页源码、Git 或截图中保留明文。普通用户只选择管理员允许的模型配置，任意供应商地址配置限管理员。

登录表单处理必填、错误凭证和会话失效，登录成功返回原目标页面。公开注册默认关闭，测试用户由管理员创建。前端路由守卫负责体验，后端每个资源接口仍需鉴权。

## 5 第四步 初始化工程和 Mock

建议目录如下。它是目标结构，初始化工具生成的文件可以调整到这里，不要求一次建立所有空模块。

```text
zhiqikeyuan/
  apps/web/src/
    app/                 路由与布局
    components/ui/       公共基础组件
    components/layout/   页面外壳
    features/            chat knowledge notes quiz reading 等业务
    services/            mock 和 http 适配器
    contracts/           从 API 生成的类型
    styles/              设计变量
  apps/api/app/
    api/                 HTTP 与 SSE 入口
    services/            业务逻辑
    providers/           模型服务适配器
    repositories/        数据访问
    workers/             解析与生成任务
  docs/                  PRD UI API 任务 决策 交接
  tests/fixtures/        可分享的固定教材与预期答案
  tests/e2e/             关键学习流程
  infra/                 部署与环境示例
```

统一使用一种包管理器；建议 npm，并提交 package-lock.json。Python 统一依赖管理和锁定方式。先运行安装、开发服务、类型检查、Lint 和生产构建，在 README 里写出确切命令。建议脚本名为 `typecheck`、`lint`、`test:unit`、`test:e2e`、`build`，这些是新项目要创建的脚本，不是声称当前目录已经存在。

前端先定义 service 接口，如 listKnowledgeBases、createSession、submitTurn、watchTask、saveNote。`mock` 与 `http` 实现相同返回结构。演示模式只用测试数据，采用确定性延迟和可选失败开关。登录也要区分演示身份与真实认证。

本地演示持久化只保存虚构资料的元数据和少量内容；用户文件与生产业务数据不依赖浏览器本地存储。给演示环境提供“重置测试数据”入口。真实构建禁止自动退回 Mock；后端断开时显示错误。

通过条件：不配置模型密钥仍能运行完整前端；切换适配器只需要配置变化和联调，不需要重写 UI；每个核心页面能切换空态、加载、成功和失败场景。

## 6 第五步 设计数据与权限

数据库迁移文件随代码提交，每次结构变化创建新迁移。所有业务数据使用稳定 ID；时间用 UTC 保存、按用户时区显示。所有属于用户的资源记录 owner_id，服务端根据登录会话确定 owner_id，不接受客户端传来的用户 ID 作为授权凭证。

| 实体 | 主要字段 | 必须保持的关系 |
| --- | --- | --- |
| users 与 auth_sessions | user_id、角色、状态、密码摘要、会话摘要、过期时间 | 密码与会话 token 不明文保存 |
| knowledge_bases | id、owner_id、name、active_index_version | 只指向完整可用的索引 |
| documents | id、kb_id、owner_id、storage_key、hash、status、version | 文件与索引任务可追踪 |
| chunks | id、doc_id、index_version、text、locator、embedding | 引用回到原文版本，向量维度统一 |
| chat_sessions | id、owner_id、mode、title、archived_at | 最近会话与历史共用同一记录 |
| messages | id、session_id、role、content、status、turn_id | 输出失败也保留状态与已生成部分 |
| turns 与 task_events | id、session_id、status、seq、payload、updated_at | 重连按事件序号恢复，事件不可串号 |
| jobs | id、owner_id、type、status、attempt、error_code | 后台处理、重试和取消持久化 |
| notebooks 与 notes | id、owner_id、notebook_id、body、source_ref、revision | 笔记来自资料或消息，正文可独立保存 |
| quizzes 与 questions | id、owner_id、source_refs、type、stem、options、answer、revision | 正确答案只在允许的服务端流程中返回 |
| attempts | id、owner_id、question_id、question_revision、response、score | 保留当时的题目和作答版本 |
| reading_states | owner_id、doc_id、version、locator、bookmarks | 每个用户独立阅读进度 |
| model_profiles 与 usage_records | 配置、能力、用途、用量、任务 ID | 密钥字段加密且不出现在普通查询中 |

扩展页需要的 books、chapters、mastery_topics、mastery_nodes、draft_versions、personas 和 memory_items 等表，在真实接入该模块时再迁移。V0.2 使用同形状的示例数据，不提前增加无用生产表。

查询链条必须检查归属。例如通过消息 ID 查询会话时，不能只确认用户已登录，还要确认该会话属于当前用户；文件下载、引用定位、任务轮询和 SSE 订阅遵循相同规则。越权统一返回不暴露资源内容的错误。

删除知识库先使其不可检索，再清理分块、索引和文件。生成中的任务需要停止或标记无效，防止删除后又写回数据。依赖它的旧回答可保留，但来源链接必须显示资料已删除。记录备份保留期，避免把立即删除承诺扩展到尚未清除的备份。

## 7 第六步 固定 API 契约

下面是新项目接口草案。先用它定义 OpenAPI，再生成前端类型和 Mock；开始实现后，所有变更在契约中先记录。错误统一返回 code、message、request_id，业务错误与网络错误分开显示。

| 方法和路径 | 用途 | 返回或约束 |
| --- | --- | --- |
| POST `/api/v1/auth/login` | 登录 | 设置受保护会话 Cookie |
| POST `/api/v1/auth/logout` | 退出 | 撤销服务端会话 |
| GET `/api/v1/me` | 当前用户 | 不含凭证 |
| GET 和 POST `/api/v1/knowledge-bases` | 列表与创建 | 游标分页、归属校验 |
| POST `/api/v1/knowledge-bases/{id}/documents` | 上传文件 | 202，document_id 和 job_id |
| DELETE `/api/v1/documents/{id}` | 移除资料 | 202，清理任务状态 |
| GET `/api/v1/jobs/{id}` | 查询后台任务 | 当前状态、阶段和错误 |
| POST `/api/v1/jobs/{id}/cancel` | 请求取消 | 返回当前状态，允许已经完成 |
| POST `/api/v1/jobs/{id}/retry` | 重试失败任务 | 新 attempt，避免重复产物 |
| GET `/api/v1/documents/{id}/source` | 原文及定位 | version、locator、受权内容 |
| GET 和 POST `/api/v1/sessions` | 会话列表与创建 | 返回 session_id |
| GET `/api/v1/sessions/{id}` | 恢复会话 | 消息、状态、可用偏好 |
| PATCH `/api/v1/sessions/{id}` | 标题或归档状态 | 检查字段权限 |
| POST `/api/v1/sessions/{id}/turns` | 提交一轮输入 | 202，turn_id |
| GET `/api/v1/turns/{id}/events` | SSE 订阅 | 支持 after_seq 恢复 |
| GET `/api/v1/turns/{id}` | 获取快照 | 已累积内容和任务状态 |
| POST `/api/v1/turns/{id}/cancel` | 请求停止生成 | cancellation_requested 或实际终态 |
| GET 和 POST `/api/v1/notebooks` | 笔记本管理 | 用户内资源 |
| POST `/api/v1/notebooks/{id}/notes` | 新建笔记 | 来源校验、正文保存 |
| PATCH `/api/v1/notes/{id}` | 修改笔记 | revision 不符返回 409 |
| GET `/api/v1/notebooks/{id}/export` | 导出 Markdown | 文件下载响应 |
| POST `/api/v1/quizzes` | 根据资料出题 | 202，job_id |
| GET `/api/v1/quizzes/{id}` | 获取练习 | 未提交前不含答案 |
| POST `/api/v1/questions/{id}/attempts` | 提交答案 | 得分、解析、引用 |
| GET 和 PATCH `/api/v1/reading-states/{docId}` | 读取或保存阅读位置 | 文档版本和定位 |
| GET `/api/v1/models` | 列出可用模型 | 只返回允许使用的配置 |
| POST `/api/v1/model-profiles/{id}/test` | 测试连接 | 需管理员权限，脱敏结果 |

相关列表和详情的其余增删改查，在对应页面任务开始前补齐方法、字段和权限；不允许 AI 在页面里临时拼接未定义地址。筛选、排序、空结果、分页和 401、403/404、409、413、422、429、5xx 都要有前端处理。

一次对话提交的示例结构：

```json
{
  "client_request_id": "uuid-generated-by-client",
  "content": "请解释这份教材中的动量守恒",
  "mode": "chat",
  "model_profile_id": "chat-default",
  "knowledge_base_ids": ["kb-demo"],
  "attachment_ids": []
}
```

client_request_id 在重试同一个提交时保持不变；服务端对“用户、会话、请求 ID”建唯一约束，避免重复生成和计费。同一个 turn 的模式、模型、资料版本在提交时固定；页面上改选模型只影响下一轮。

SSE 事件的示例：

```text
id: 12
event: message.delta
data: {"turn_id":"turn-01","seq":12,"delta":"在没有外力作用时"}

id: 13
event: citation.added
data: {"turn_id":"turn-01","seq":13,"source_id":"s1","doc_id":"doc-01","version":1,"locator":{"kind":"pdf_page","page":12}}

id: 14
event: turn.completed
data: {"turn_id":"turn-01","seq":14,"message_id":"msg-02"}
```

事件类型至少定义 turn.started、message.delta、citation.added、task.progress、turn.completed、turn.failed、turn.cancelled。前端按 turn_id 和 seq 去重；刷新先获取快照，再从 last_seq 订阅，服务端补发之后的事件，避免快照和订阅之间漏消息。事件超出保留窗口时返回需重新获取快照的状态。

先 POST 创建任务，再 GET 订阅事件。浏览器 EventSource 无法任意设置 Authorization 头，因此建议同源 HttpOnly 会话 Cookie；如必须使用令牌，则用 fetch 流读取，并设计过期刷新。跨域、Cookie、CSRF 和 CORS 策略必须一起确定。

SSE 断开只代表连接断开，不能自动把任务当作失败或重新提交。收到终态事件后停止 loading；取消先进入 cancelling，只有服务端确认后进入 cancelled。失败和取消保留部分输出，重新生成时创建新 turn，旧输出不被覆盖。

## 8 第七步 实现真实学习流程

### 8.1 资料进入知识库

1. 服务端校验身份、文件大小、类型与可接受内容，分配 document_id 和私有存储路径。
2. 保存文件、内容哈希和 queued 状态，创建解析任务，返回 202。
3. Worker 提取文字及页码或段落定位；无文字、加密文件、损坏文件明确失败。
4. 按标题和段落切分，保留 chunk_id、doc_id、version 和 locator。初始分块可从约 500 至 800 token、重叠 80 至 120 token 调起，并用测试集评估后调整。
5. 调用嵌入模型，批量写入暂存索引；确认全部必需分块写入成功后切换为 ready。
6. 页面轮询或订阅任务进度。重新索引时活动旧版本继续可用，新版本验证后再切换。

相同文件去重首先限制在用户或资料库范围，不能通过去重响应暴露其他用户是否上传过某个文件。任务重试利用哈希与版本避免重复分块。文件系统保存成功但数据库事务失败时，要有孤立文件清理机制。

### 8.2 检索和生成回答

先判断用户选择的知识库是否可用，再对当前版本检索。首版采用向量检索，可按测试结果增加关键词混合检索和重排，不同时引入多套引擎。检索结果分配服务端 source_id，把原文、来源与定位作为受限上下文传给模型。

模型输出的引用 ID 必须属于本轮实际检索结果；校验无法对应的引用并提示。检索结果不足时说明资料依据不足，可以向用户请求补充材料。来源检索和引用定位由程序保证，不能依赖模型随意生成 URL 或页码。

先记录开始状态和输入，再逐段保存输出与事件，最后持久化完成状态和用量。把提交成功、检索完成、模型开始输出分别展示为真实状态；无法准确估计进度时使用阶段文字，不虚构百分比。

### 8.3 出题和保存

出题沿用已授权资料检索结果，并用 JSON Schema 约束题型、题干、选项、正确答案、解析和 source_id。校验单选只有一个正确项、多选答案在合法选项集合内、判断题值类型正确、题数满足约束、引用可解析。

结构校验失败最多做有限次数的修复尝试，仍失败则返回任务错误；不能把半成品题目当成生成成功。答案保存在服务端，提交后再按评分规则返回。把有价值的解析存入笔记时，同时保留 source_ref 和原问题链接。

### 8.4 模型供应商适配

适配层统一流式文本、终态、错误、用量和结构化输出等语义；每家供应商内部处理自己的鉴权、协议和事件格式。能力标记初始为未知，验证后设为支持或不支持。不要假设所有“兼容”端点都支持相同参数。

首期只需要普通文本和流式输出。结构化结果如果不能原生保证，先校验再有限重试。统一处理超时、429、鉴权失败、内容被拒、网络中断和余额不足。已经输出部分内容后发生故障，保存中断状态；不要自动在另一个模型重新生成并拼接成同一答案。

## 9 第八步 联调和质量检查

先用同一 API 规范让 Mock 与真实后端执行一组契约样例，确认字段、空值、错误和事件一致。然后依次联调登录、上传、索引、问答、引用、出题、笔记和历史恢复。所有阶段的证据标记环境和代码版本。

视觉检查固定 1440×900、1024×768、390×844，截图统一时间、字体、主题和测试数据，关闭非必要动画。每页按结构、尺寸间距、字体颜色、状态和响应式分别记录问题，优先修复结构和交互问题。像素差异只能辅助检查，不能用一个“还原度百分比”代替人工对照。

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| E01 | 无数据首次访问 | 空状态说明明确，能创建首个资源 |
| E02 | 上传合法 PDF | 状态顺序正确，可预览并可检索 |
| E03 | 上传超限或损坏文件 | 显示具体原因，不留下可检索的假记录 |
| E04 | 提问教材内问题 | 流式回答，引用可定位且支持结论 |
| E05 | 提问资料外问题 | 明确依据不足，不伪造资料引用 |
| E06 | 发送按钮重复点击或请求重试 | 只建立一次逻辑生成 |
| E07 | 输出途中断网再恢复 | 恢复同一 turn，无重复文本或重复计费提交 |
| E08 | 生成中停止并刷新 | 以服务端真实状态恢复，不永远转圈 |
| E09 | 保存笔记并重新登录 | 内容和来源仍在，保存失败不冒充成功 |
| E10 | 答题前检查网络响应 | 无正确答案泄露；提交后结果正确 |
| E11 | 账号 A 访问 B 的 ID | 文件、消息、任务与事件均不可读取 |
| E12 | 修改笔记产生版本冲突 | 409 与冲突提示，不静默覆盖 |
| E13 | 手机上输入中文和展开抽屉 | 不误发，不遮挡输入框，内容不横向溢出 |
| E14 | Worker 在任务中途重启 | 任务可识别、恢复或明确失败并可重试 |
| E15 | 删除资料后点击旧引用 | 显示不可访问，不跳到其他资料 |
| E16 | 从备份恢复到新实例 | 数据、文件和关键关联一致 |

单元测试重点覆盖评分、引用解析、权限判断、状态转移和事件去重。端到端测试覆盖关键学习流程和异常恢复。不要为了测试数量给每个静态标题写测试。若只是修改间距或文案，截图检查和相关页面验证即可。

通过条件：类型检查、Lint、生产构建和关键流程测试通过；高风险问题关闭；尚未实现的模块与已接通模块在发布环境中清晰可分辨。

## 10 第九步 部署和运行

开发环境运行 web、api、worker、PostgreSQL 和 Redis；测试环境采用与正式环境一致的容器定义。服务器容量先按测试数据测量，模型推理使用外部 API 时无需为了网页本身采购 GPU。扫描识别或本地模型另做容量评估。

1. 创建独立测试域名，配置 HTTPS 和同源反向代理，让 `/api/v1` 指向后台。
2. 构建固定版本镜像，记录 Git SHA；密钥由服务端环境或秘密配置注入，样例文件只写占位符。
3. 创建数据库及文件持久卷；运行迁移，创建测试账户和小型资料集。
4. 配置队列、并发、请求大小和超时；SSE 关闭代理响应缓冲，定期心跳，验证实际流式响应。
5. 执行 E01 至 E16；检查跨账号访问、重启恢复和真实模型限流。
6. 生成备份，恢复到隔离实例，核对文件与数据库关联；向用户试用前完成这一轮恢复。
7. 小范围开放，收集错误与费用；通过后以同一构建产物发布正式环境。

日志至少包含 request_id、user_id 的受控标识、turn_id、job_id、供应商错误码、阶段耗时和用量；不记录明文密钥或整份私人教材。监控队列积压、失败率、首字耗时、终态遗漏和存储容量。

回滚前先判断迁移是否向后兼容。常规回滚切回上一镜像；不兼容的数据迁移必须有单独恢复步骤和已验证备份，不能盲目运行 downgrade。备份应同时覆盖数据库、文件和必要加密配置，按目标恢复点保持一致。

通过条件：从空环境按 README 能部署；重启不丢数据；SSE 经真实域名工作；备份能够恢复；发生模型故障时用户看到可理解的失败和后续操作。

## 11 第十步 扩展功能和后续维护

扩展顺序建议为协同写作、章节书本、学习路径、角色伙伴、可编辑记忆，最后才是外部智能体、复杂研究和任意代码执行。每项扩展先增加一个真实用户场景、接口、状态和错误处理，再扩大能力。

书本分章节任务执行，避免整本生成作为一个不可恢复请求。学习路径根据客观题表现和用户目标定义掌握规则。自动记忆必须可查看、修改和删除。运行用户或模型生成的代码需要独立执行隔离、资源限制和网络策略，作为专门项目评估，不直接在 API 进程内执行。

每周集中处理依赖更新、错误回归和成本。回收过期任务事件时保留最终消息和必要状态；更换嵌入模型先重建索引；修改提示词后运行同一测试集并记录版本。不要在正在试用的主环境中同时更换模型、检索参数和页面结构。

## 12 每个任务的完成定义

一个任务完成至少需要：改动符合任务范围；重要状态可演示；接口契约一致；相关检查实际执行且结果明确；截图或请求证据可复查；交接记录列出已完成、未完成、运行命令和下一任务。未执行的检查写“未执行”并给出原因，不能写“应当通过”。

项目负责人只需要每次核对三个问题：本次能实际操作什么；失败时会发生什么；交给下一位 AI 能否从文件中恢复上下文。对应的可复制任务文本见《03_AI执行任务包》。
