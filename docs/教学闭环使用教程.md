# 教学闭环使用教程

> 面向教师使用者。读完这篇，你能独立把一个班从「原卷 + 小题得分」走到「学情报告 → 针对性练习 →
> 新成绩回流 → 学情驱动教案」，并知道每一步的闸门、口径和常见故障怎么处理。
>
> 事实边界：本篇描述的按钮名与流程来自**实际运行过的界面**（2026-10-06 复核）；未亲手点过的页面
> 只写到接口与默认行为层面，已在文中标注「以实际页面为准」。

---

## 1. 闭环长什么样

```text
        ┌─ 独立知识点 ─┐                         ┌─ 题库（正式题） ─┐
        │  code/别名   │                         │  导入→校对→审核  │
        └──────┬──────┘                         └────────┬────────┘
               │ 关联                                    │ 选题
 名单/班级 ──▶ 原卷（DOCX）──▶ 施测 ──▶ 小题成绩 ──▶ 学情报告 ──▶ 针对性练习 ──▶ 新施测
   │            │确认闸门      │参测快照   │四态区分     │班级/学生/     │复核+审核     │
   │            └─ 不可变修订  └─ 冻结     │ 0≠空白      │题目证据       │导出 DOCX/XLSX│
   │                                      └────┬────────┘               │
   └──────────────────── 学生与班级 ───────────┘                        │
                                        ┌───────────────────────────────┘
                                        ▼
                                 回流新成绩 ──▶ 新学情报告（对比"需巩固"）
                                        │
                                        ▼
                         教案工作台：学情驱动 AI 调整 / 规则填充 ──▶ Word / PDF
```

一句话：**原卷定结构、成绩定事实、学情定优先级、练习做干预、教案做课堂落地**。每一环都只认上一环
"已确认"的产物，AI 只出**待教师选择的建议**。

## 2. 开工前的四件事

### 2.1 启动服务（Windows / 仓库根目录）

```powershell
npm.cmd run setup:api     # 首次：创建后端环境（uv sync）
npm.cmd run dev:api       # 后端 http://127.0.0.1:8000
npm.cmd run dev           # 前端 http://127.0.0.1:5173（首页 /chat）
```

> 前端端口必须落在后端白名单内（默认 `5173`/`5174`）。换端口要同时改后端的
> `ZQKY_ALLOWED_ORIGINS`，否则所有写操作会被 403 `FORBIDDEN_ORIGIN` 拒绝。

### 2.2 向量库与本地 Embedding（RAG 相关功能必需）

```powershell
npm.cmd run rag:db:start     # 起 Qdrant（127.0.0.1:6333）
npm.cmd run rag:db:status    # 查看容器状态
```

本地 Embedding 走 Ollama（`bge-m3`）。**两者缺一，检索就是"不可用"**，页面会在「学习问答」顶部
明确报出原因（不会假装成功、也不会给你空结果）。

### 2.3 模型与连接（决定"谁来生成"）

设置 → 模型与连接：

| 分页 | 用途 | 要点 |
| --- | --- | --- |
| 问答模型 | 连接与模型目录 | 云端连接填 API Key（只存后端）；本机服务（Ollama/vLLM/LM Studio）免 Key |
| 默认模型 | **全局默认问答模型** | **教案生成未显式选择时用它**；**RAG 知识点概括只认它** |

**当前口径（2026-10-06 起）**：

- **教案生成只使用云端模型**：模型下拉里**不会出现本机部署档案**；后端解析到本机连接也会以
  422 `LESSON_MODEL_NOT_CLOUD` 拒绝，并且**一个模型请求都不会发**。
- **RAG 知识点概括只用「全局默认问答模型」**，且**同样不使用本机模型**：没配默认模型、或默认模型是
  本机部署时，概括状态直接显示**不可用**并说明原因，绝不悄悄回退本机。
- 概括状态是**配置级检查**（只解析默认档案并判定云端，不向云端发推理调用）。所以"可用"只代表
  **配置就绪**，不代表凭证/额度已实测；真实失败会在调用时原样上报。

### 2.4 教材入库并建立索引（想用教材依据/RAG 才需要）

教材资料库 → 上传文件 → 校对解析与分类 → 提交入库；随后到 设置 → **Embedding 模型** →
按提示「检测」并「保存配置」→ **开始重建**。

- 发布是**原子**的：新索引代完成前，旧索引代继续可用。
- 「任教范围」（学段/学科/版本 + 选定书册）由**当前索引代**决定；范围没就绪时，问答与教案里的
  教材相关功能会明确报"未就绪"。
- 重建会把所选配置对本机**全部教材**重新向量化，耗时与书册数成正比。

**自检**：学习问答页顶部一排状态（检索 / 本地概括 / 原文访问 / 任教范围 / 人工教学质量）全绿即可开跑。

## 3. 第 0 步：独立知识点

入口：导航 →**知识点**。

1. 表格导入：知识点页的「表格导入与校对」上传 CSV/XLSX → 预览行 → 整批确认（确认是**幂等**的，
   响应丢失可原样重发）。
2. 手动新建：名称、**编码（同学科内唯一）**、父级编码、别名、排序。
3. 教材依据（可选）：在「教材依据」里选书册 + 区间，服务端会校验并冻结标题；教材不可用时报
   `TEXTBOOK_EVIDENCE_UNAVAILABLE`（**"读不到"不等于"没有依据"**）。
4. AI 候选（可选）：给出证据与要求 → 生成**待确认批次** → 你逐条确认后才进入正式知识库。

口径：**AI 候选永不自动发布**；知识点名称只存在修订表里，改名生成新修订。

---

## 4. 第 1 步：班级与名单

入口：**施测与成绩** → 步骤页签 `1 名单`。

1. 「新建班级」：名称、学年、年级。
2. 上传名单（CSV/XLSX）→ 预览行与身份建议（新建/合并/转班）→ 确认导入。
   - 学号按**文本**保留，前导零不会被吃掉。
   - 名单里没出现的旧学生**不会自动退班**；转班会保留旧归属历史。
3. 名单变化后回到施测/成绩页，点「刷新成员」重新读取。

---

## 5. 第 2 步：原卷（DOCX）

入口：**施测与成绩** → `2 原卷`（页面）或 教案/题库导入入口（看你从哪进）。核心是三步：
**导入 → 逐题校对 → 确认**。

导入后系统给出候选题目与原文块归属，你要检查：

| 检查项 | 说明 |
| --- | --- |
| 题号与计分叶 | 只有**计分叶**（如 `5(1)`、`16(2)`）承载分值；父题（`16`）是容器不计分 |
| 满分标记 | 取「（N 分）」/「满分 N 分」的首个匹配；**找不到就留空并标 `ITEM_SCORE_MISSING`（阻断）**，不会猜 |
| 内容归属 | 每个原文块要么归某题、要么是共享材料、要么待你指定；**未归属块会阻断确认** |
| 分节标题 | 「一、选择题（共40分）」这类标题是**结构边界**：它既不进上一题的题干，它的"共 N 分"也**不会**变成上一题的满分；该块需要你**指定归属或排除** |
| 独立子题 | 独立成段的「（1）」及其后续正文归到 `父号(子号)`（如 `15(1)`），父容器不吸收子题内容 |
| 重复题号 | 同一题号出现两次会并入该题并记录阻断问题，需人工拆分 |

**确认闸门**：只要还有阻断问题（缺分、重复题号、解析损失、未归属块、总分不一致）或未归属原文块，
确认就会被 422 拒绝并逐条列出。通过后才生成**已确认修订**，它是后面施测唯一认可的原卷版本。

口径：**已确认修订不可变**；要改就生成新修订，旧修订与历史保留可查。

---

## 6. 第 3 步：施测

入口：**施测与成绩** → `3 施测`。

1. 选「原卷」：只能选**已确认修订**。
2. 选班级 → 系统按名单带出参测人次；可逐个调整**出勤**（正常/缺考/免考）。
3. 填标题、日期 → 「创建施测」。
4. **参测名单会被冻结成快照**：之后的名单变化不会改写这次施测。
5. 若施测日期早于名单归属的起始日（例如补录去年的考试），系统会要求你**显式确认本次班级并写依据**
   （`classConfirmed=true` + 备注），它**不会自动修改归属历史**——这是设计如此。

---

## 7. 第 4 步：成绩（本闭环最需要耐心的一步）

入口：**施测与成绩** → 选中施测 → `4 成绩`。

1. **上传成绩表**（教师原始 XLSX/CSV）→ 生成待校对批次。
2. **列映射**：把每个计分叶映射到表格列（表头行、学号列、姓名列、出勤列可选、总分类可选），
   点「保存映射并重算」。未映射按 `missing` 处理。
3. **逐格校对**——系统严格区分四种状态，务必看清图例：

| 状态 | 含义 | 计分 |
| --- | --- | --- |
| 有效 | 教师给了分，**0 也是有效分** | 计入 |
| 空白 | 单元格没填 | **不补 0**，需你逐个承认或修正 |
| 缺考 | 按人次出勤状态登记 | 不计入 |
| 免考 | 明确免考 | 不计入、不参与总分核对 |

4. 「承认」与「确认」：确认后的成绩修订**不可变**；要改分就生成新版本，历史与审计保留。
5. **响应丢失可原样重放**：确认请求带 `submissionId` 幂等键，重发不会重复入库。

口径：**不自动评分、不补零、不反推、不预测掌握概率**；总分只用有效分核对。

---

## 8. 第 5 步：学情报告

入口：导航 →**学情分析**。

1. 「选择固定成绩与参测人次」：选**施测** → 选**固定成绩修订** → 可勾选部分人次 → 「创建本次报告」。
2. 报告是后台任务（作业引擎），完成后在「固定报告历史」里出现，点开看「本次固定依据」：

| 视图 | 看什么 |
| --- | --- |
| 班级依据 | 班级 × 知识点：选定/有效/本次需巩固/信息不全/无有效依据/满分 与比例 |
| 学生依据 | 学生 × 知识点：本次观察结论、四态计数、有效得分，可展开「全部题证据」 |
| 全部题证据 | 逐题的小题事实 |
| 教师备注 | 注明班名缺失等口径信息 |

3. 规则是**可解释的固定规则**（`any_loss_v1`）：**任一关联小题有效得分低于满分 → 本次需巩固**；
   综合题的具体错因仍由教师确认。
4. 口径红线：这里的比例是**本次需巩固比例**，**不是掌握率**，不能当长期能力判断。

---

## 9. 第 6 步：针对性练习

入口：报告页底的「选择目标，创建针对练习」，或导航 →**针对练习**。

1. 选目标知识点（来自报告）+ 约束（题量/题型/难度/"排除原测题"/"排除内容重复题"）→ 创建。
2. 系统从**正式题库**选题并给出缺口提示（缺题**不会**自动放宽条件）。
3. **复核计分结构**：「完整题目与计分叶审阅」里核对每题题干、计分叶、知识点关联与来源。
4. 「审核」：审核后产生**只读修订**（`v1·已审核`）。
5. 「固定审核版本导出」：
   - **学生 DOCX**（不含答案解析）
   - **教师 DOCX**（含答案与解析；图片为文本投影时会提示你对照原题）
   - **成绩模板 XLSX**（**必须在本练习转换施测之后**才生成；空白不补 0）

---

## 10. 第 7 步：回流（把练习变成新成绩）

入口：**针对练习** → 「转换为施测，回到成绩工作区」。

1. 选日期与班级 → 「转换固定练习为施测」：系统按审核修订建一份**新施测**（不动原施测）。
2. 到 **施测与成绩** → `4 成绩`：上传教师填好的成绩模板 → 列映射 → 校对 → 承认 → 确认。
3. 回到**学情分析**：用新成绩修订创建**新报告**。
4. 对比两份报告的「本次需巩固」——这就是"干预有没有效果"的可见证据。报告会标明练习来源，
   使证据可追溯。

> 注意：系统**不会**替你判断"教学有效"，它只保证成绩被严格重算；结论由你看报告得出。

---

## 11. 第 8 步：学情驱动教案调整

入口：导航 →**教案工作台**；从报告页也可以直接「以本次固定学情准备教案」跳转。

### 11.1 发起 AI 调整（生成建议）

面板「班级、固定学情与生成来源」里把这些**凑齐**（缺一项会被前置检查拦下）：

| 项 | 说明 |
| --- | --- |
| 教案学科 / 单一班级 | 生成上下文 |
| 固定 ready 学情 | 选一份已准备的报告 |
| 明确选择知识点 | 勾选本次课堂聚焦的知识点（最多 50） |
| **模型档案** | **只列云端档案**；未显式选择时自动选中「全局默认问答模型」 |
| 真实教材切片 | 选年级/版本 → 「读取可选教材」→ 选固定修订 → 设切片起止 → 「读取并核验教材切片」 |
| 课堂时长 | 5–180 分钟 |
| **教师要求** | **必须至少 1 个字**（这是后端契约；写清课堂诉求，别写学生姓名/学号） |

然后点「保存当前稿并生成 AI 候选」。生成是后台任务：成功后出现**逐字段差异**（当前正文 vs AI 候选）：

- 勾选想采纳的字段 → 「仅采用所选完整字段」（未建议的字段不能勾）
- 不满意就「明确拒绝候选」；两者都会终结该候选

**AI 只出建议**：你的标题、课时、课型、反思不会被改；未采纳的字段保持原样。

### 11.2 没有模型也能用：要求填充（规则）

「要求填充」页签把**你写的备课文本**按"字段：内容"解析成教案字段：

```text
课题：解一元一次方程（第一课时）
总课时：2
本节课：1
课型：新课
核心素养目标：……
教学重、难点：……
教学设计：……
教学过程：
情境导入 | 教学设计 | 二次备课
练习与作业：……
```

先「识别填充内容」预览 → 「确认填入教案」→ 再在「逐项填写」里微调。**这条路径不连模型**，离线可用。

### 11.3 保存与导出

- 后台教案：右上「后台稿已保存」表示已落库；历史修订只读可查、可复制为新稿。
- 导出：顶栏「导出教案」→ **导出 Word / 导出 PDF**；也可用浏览器打印（打印会冻结当前内容）。

## 12. 业务护栏（这些红线不会因为方便而打破）

1. 成绩只接受**教师已给的分**：不自动评分、不补零、不反推、不预测掌握概率。
2. 0 与空白、缺考、免考**严格区分**；空白必须逐个承认。
3. 已确认的原卷修订、已确认的成绩修订**不可变**；修改生成新版本并保留审计。
4. AI 输出一律是**待教师选择**的候选，不直接改正文；教案的教师字段有自己的保护栏。
5. 学情比例是**本次需巩固**口径，不是掌握率；综合题错因由教师确认。
6. 缺失就报缺失（缺分、未归属、范围未就绪、检索不可用），**不伪造成功、不返回空结果蒙混**。

## 13. 常见问题排查

| 症状 | 常见原因 | 处理 |
| --- | --- | --- |
| 顶部「检索/概括 不可用」 | Qdrant 没起 / Ollama 没起 | `npm.cmd run rag:db:start`；确认 Ollama 在 11434 |
| 「本地概括 不可用」 | 没配**全局默认问答模型**，或默认是本机部署 | 设置 → 默认模型 选一个**云端**档案 |
| 教案生成下拉里看不到我的本机模型 | 设计如此：**教案生成只允许云端** | 用云端档案；本机模型只用于问答 |
| 生成任务失败：`UPSTREAM_TIMEOUT 等待模型响应超时` | 产品对**非流式**生成默认只等 **30 秒**；`reasoning=max` 档模型写完整教案要约 90 秒 | 把该档案的推理关掉/调低，或换更快的模型；**当前没有超时配置项**（已登记为待修） |
| 点生成后报"教案请求字段不符合契约。" | 多数字段没填全，最常见是**「教师要求」空白** | 补写教师要求（≥1 字），并核对班级/报告/知识点/教材切片/时长 |
| 所有写操作 403 `FORBIDDEN_ORIGIN` | 前端端口不在后端白名单 | 用 5173/5174，或同步改 `ZQKY_ALLOWED_ORIGINS` |
| 原卷确认被 422 拒绝 | 有阻断问题或未归属块 | 按报错逐条修：补分/拆分重复题号/指定归属或排除 |
| 成绩确认被拒："空白单元格未承认" | 有空白格未处理 | 逐格承认或修正；**不要**用 0 覆盖空白 |
| 教材切片核验失败 | 索引代未就绪 / 区间越界 / 范围不匹配 | 检查 设置 → Embedding 模型 索引状态；确认区间在字符数内 |
| 施测创建被 422 `PARTICIPANT_CLASS_UNCONFIRMED` | 施测日期早于名单归属起始日 | 勾选**显式确认本次班级**并填写依据 |

## 14. 一页速查：最小可跑通路径

1. 起服务：`dev:api` + `dev`，需要 RAG 时再 `rag:db:start`。
2. 设置：接一个**云端**连接 → 「默认模型」选它。
3. 知识点：导入 `独立知识点.csv` 并确认。
4. 名单：建 2 个班，导入名单。
5. 原卷：导入 DOCX → 补分/归属 → 确认。
6. 施测：选原卷 + 班级 → 创建（必要时显式确认班级）。
7. 成绩：上传 `初测小题成绩.csv/xlsx` → 列映射 → 处理空白 → 承认 → 确认。
8. 学情：创建报告 → 看班级依据（本次需巩固）。
9. 练习：从报告创建 → 复核 → 审核 → 导出教师/学生 DOCX 与成绩模板。
10. 回流：练习转施测 → 上传教师填分 → 新报告对比。
11. 教案：教案工作台凑齐条件 → 生成 AI 候选 → 勾选字段采用 → 导出 Word/PDF。

> 全部数据仅存本机；API Key 只在后端 `apps/api/.env`，不会进前端、日志或截图。
