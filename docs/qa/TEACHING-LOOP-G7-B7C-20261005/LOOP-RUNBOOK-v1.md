## 二、"真的走通"还差什么

1. **真实模型（AI 教案那一步）**：现在链上那一步是手写替身。真实模型要过 B7-C 前的三项前置：可信 host、模型专属 proof、结果入口 live provenance；其中 proof 卡在"输入 token 上界"（官方只有估计口径的分词器；详见 [SCOPE-INPUT-deepseek-flash-v1.md](b7c/SCOPE-INPUT-deepseek-flash-v1.md)）。**需要用户选 A（维持严格，真实模型不发）或 B（接受官方分词器计数为输入预留基准并结算对账）。**
2. **真实数据**：第 1 步需要三份教师文件——**班级名单 XLSX/CSV、原卷 DOCX、小题得分 XLSX/CSV**（已有固定匿名样本可先演示）。用户文件放哪、是否允许在本机数据根写入，需要用户明确；CTRL 不覆盖用户在用数据。
3. **教师动作（系统不做）**：五字段选择、练习审核、给分、回流确认；`teacher_review_pending` 只能由真人关闭。
4. **另行待验（不阻塞六步机制走通）**：RAG 相关性拒答闸门（RAG-REL OPEN）、Word/WPS 原生排版（not_run）、实际 PDF 保存。

## 三、最小真实走通路径（建议执行顺序）

1. 本机起隔离实例（TEMP 数据根）或用用户自己的数据根（后者需授权）。
2. `/assessments`：导入名单 → 导入原卷并逐题确认（题号/计分叶/知识点）→ 建施测（单班）→ 导入小题得分并映射/校对/承认/确认。
3. `/learning-analysis`：选该成绩修订 → 选人次 → 生成 `any_loss_v1` 报告 → 核对需巩固知识点。
4. `/lesson-plans`：导入/创建后台教案 → 打开"学情驱动 AI 候选"面板 → 选该报告/单班/KP/核验教材、确认题与审核练习、模型档案 → 生成候选（此处是替身或真实模型的分岔点）→ 教师勾选五个完整字段 → 仅采用所选字段。
5. `/learning-analysis` → 建立针对练习 → `/practices` 复核/审核 → 导出学生卷教师卷与成绩模板。
6. 用成绩模板施测并录入 → 走第 1 步成绩流程 → 生成新报告完成回流。

## 四、边界

闭环走通＝按上图六步都能用真实业务服务跑完并留下可核收据；它**不**等于教学质量通过、教师认可、原生排版合格或 RAG 相关性通过——这四项分别待验。真实模型与真实数据两项均需用户明确授权后才能执行。
