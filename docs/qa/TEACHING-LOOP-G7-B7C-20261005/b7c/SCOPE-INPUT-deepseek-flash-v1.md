## 官方协议事实（只读查询，2026-10-05）

来源：[DeepSeek Chat Completions API 文档](https://api-docs.deepseek.com/api/create-chat-completion)（reasoning 指南页未返回相关章节）。

- usage 字段：`prompt_tokens`（**等于 prompt_cache_hit_tokens + prompt_cache_miss_tokens**）、`completion_tokens`、`total_tokens`（prompt+completion）、`prompt_cache_hit_tokens`、`prompt_cache_miss_tokens`、`prompt_tokens_details.cached_tokens`、`completion_tokens_details.reasoning_tokens`（“Tokens generated by the model for reasoning”）。
- `max_tokens`：定义为“生成的 completion 的最大 token 数”，范围 1–384K；默认 8K（非思考）/64K（思考）/128K（`reasoning_effort=max`）。**文档没有说明 `max_tokens` 是否包含 `reasoning_tokens`**。
- `reasoning_effort` 允许值：**[none, low, high, max]**，默认 high；官方原文：“none disables thinking mode”“low / high / max enable thinking mode”；minimal→low、medium/xhigh→high。
- `thinking.type` 允许值：**[enabled, disabled]**，默认 enabled —— 官方支持显式关闭思考。
- `thinking` 对象**只有两个字段**：`type` 与 `reasoning_effort`（none/low/high/max，默认 high）；**不存在 `budget_tokens` / `max_thinking_tokens` 或任何给推理 token 直接封顶的字段**；官方也没有任何一句说明 `max_tokens` 是否包含推理 token。
- 响应字段：`content`（最终回答）与 `reasoning_content`（“For thinking mode only … before the final answer”）分离；只取 `content` 即不含推理文本。
- **官方离线分词器**：[Token & Token Usage 页](https://api-docs.deepseek.com/quick_start/token_usage) 提供下载包 `https://cdn.deepseek.com/api-docs/deepseek_v4_tokenizer.zip`，说明为“You can run the demo tokenizer code in the following zip package to calculate the token usage for your input/output.”
  - 同页并列的字符比例（“1 English character ≈ 0.3 token”“1 Chinese character ≈ 0.6 token”）标注为估计，且明说“This is an estimate only; the actual number of tokens produced during processing may vary slightly, so refer to the usage returned by the API as the source of truth.”
  - 页面**未声明**该分词器对应哪个具体模型名，也没有发送前的 token 计数 API 端点。
- [上下文缓存页](https://api-docs.deepseek.com/guides/kv_cache)：确认 usage 含 `prompt_cache_hit_tokens`（“The number of tokens in the input of this request that resulted in a cache hit.”）与 `prompt_cache_miss_tokens`；**未说明缓存命中是否计费/折扣**，也未涉及推理计费与 `max_tokens` 包含关系。

## 输入上界的结论（本批安全判据下）

- 现行生产代码只给到**字节/UTF-16 字符上限**（128,000 UTF-16 单位、256 KiB），仓库内无该模型的官方精确分词计数。
- 官方离线分词器是唯一官方计数工具，但官方原文把它与“estimate only / 以 API 返回 usage 为准”并列，且未声明与 `deepseek-flash` 的逐字对应；用它作为“保证不会被超过的上界”属于**估计**，与本批“字符估计不作证明”的规则冲突。
- 因此：**输入 token 的完整上界在发送前无法证明** → 按本批规则维持 `BILLING_BOUND_UNSUPPORTED`、真实发送 0。输出/推理侧可由“关闭推理 + wire `max_tokens=16384`”解决（官方 none=关闭思考）。是否接受“官方 v4 分词器精确计数 + 结算时按返回 usage 对账（超出即 STOP，但费用已发生）”作为输入预留基准，属于用户的风险接受决定，CTRL 不自行放宽判据。


## 生产链对"只保留 content"的现状（只读代码核对）

- 教案生成走非流式 `_complete()`：只取 `choices[0].message.content`（`text_from_content`），`reasoning_content` 不进入候选/应用/导出（[openai_chat.py:131-134](apps/api/app/providers/llm/openai_chat.py#L131)）；流式聊天另有 reasoning 独立通道，但本期试评不用流式。
- 该档案（providerId `custom`、modelId `deepseek-flash`）不匹配现有 custom 推理样式表（仅 `deepseek-v4-pro`/`deepseek-reasoner`/`deepseek-r1`），故请求**不带 `thinking` 字段**，而是顶层 `reasoning_effort`（现为 `max`，[reasoning_params.py:115-120,142-153](apps/api/app/providers/llm/reasoning_params.py#L115)）；`reasoning_effort` 在生产 wire 允许集合内（[privacy.py:171](apps/api/app/services/lesson_generation/privacy.py#L171)）。
- 若把档案 `reasoningEnabled` 置 false：resolved_effort 变 `none` → wire 变顶层 `reasoning_effort:"none"`（官方语义=关闭思考）；这属于改变被测配置，必须重新冻结配置指纹/wire SHA 并重新证明，不能沿用旧结论。


## 具体不支持项（因此仍 BILLING_BOUND_UNSUPPORTED / real0）

1. **输出/推理上界不可证明**：`max_tokens=16384` 与 `reasoning_tokens` 的包含关系官方未声明，档案又是 reasoning=true/effort=max；无法给出完整 output+reasoning 上界。
2. **输入 token 上界不可证明**：现有只有字节/UTF-16 字符上限，仓库内没有该模型的官方 tokenizer/计数证据，字符估计不作证明。
3. **usage 维度**：官方 usage 会带 cache/reasoning 明细；结果入口现只接受 `prompt_tokens/completion_tokens/total_tokens`，其他维度按“未证明计费维度”硬拒（[trial_result_check.py:413-419](scripts/teaching-quality/trial_result_check.py#L413)），需先做 proof/结果入口升级并独立验收。

5. **结果入口 live provenance 仍显式拒绝**（`LIVE_RESULT_SUPPORT_UNREGISTERED`）。
