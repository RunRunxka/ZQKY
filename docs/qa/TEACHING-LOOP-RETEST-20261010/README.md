## 3. 发现：P2 清理链断点——已审核练习钉死来源报告与来源施测（实证）

**现象**：练习一经「审核」，该练习集**永远不能彻底删除**（设计：reviewed 修订受 DB 触发器保护，`PRACTICE_IN_USE` 提示「已审核版本只能归档」）。而报告删除守卫把 `practice_sets.analysis_run_id`（实外键）计入引用（含已归档练习），于是**来源报告被永久钉住**；该报告又使来源施测的 `analysisRuns` 计数恒非零 → **施测、成绩版本、导入批次随之全部无法彻底删除**。用户按守卫提示"先处理相关数据"，走到练习后只剩"归档"一条路，归档也不解除钉住——**无出路**。

**实证**（正式数据，两条守卫均正确拒绝，组合构成死结）：

```
DELETE /analysis-runs/611248ff… → 409 ANALYSIS_RUN_IN_USE
  "学情报告仍被引用，不能删除（针对练习 1 条、教案引用（修订/生成输入/AI 候选） 4 条）；请先处理相关数据。"
  details.counts = {practiceSets: 1, lessonReferences: 4}
DELETE /practice-sets/01e7ac02…?expectedRevision=2 → 409 PRACTICE_IN_USE
  "练习集仍被引用，不能删除（已审核版本 1 条、导出记录 1 条、施测转换 1 条）；已审核版本只能归档；
   如需修改请从审核版建立新草稿。"
```

（教案引用 4 条可删——教案有 L1 的彻底删除；删完后 practiceSets:1 仍是死结。）

**用户正式数据里的同类链**：`闭环初测·测试二班`（施测 `026c4c74…` → 成绩 `9d7149d1…` → 报告 `9339cb32…` ← **练习 `a9c788e7…`（已审核、已归档）**）——该链的施测/成绩版本/报告当前同样无法彻底清理。

**建议方向（需产品裁定，本次未实施）**：① 提供受守卫的"彻底删除已审核练习"（沿用触发器受控摘除先例；需定义不可变导出/转换产物的处置）；或 ② 保持不可删口径，但在报告/施测守卫消息中**明示**"来源练习为已审核版本，该链只能归档、不可彻底清理"；或 ③ 允许在"练习归档"前提下断开 lineage 引用（语义最重，谨慎）。
