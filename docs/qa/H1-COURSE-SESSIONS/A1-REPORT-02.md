## 3. r2 新发现问题（均低危，**无产品功能缺陷**）

1. **低｜边界承诺弱化 + 文档不准（F4 残留）**：收缩循环无法压缩固定行（`课程名称：`、`下一个未完成单元：`），固定行本身超预算时循环不收敛并原样返回。最小复现（函数级，A1 实测）：`syllabus.nextTitle = '单'.repeat(3000)` → 返回 **3096 字符 > 2400**；`name` 同理（课程名有 `maxLength=60` 不可达）。**UI 可达**：大纲编辑 textarea 无 `maxLength`、`parseSyllabusText` 不截断。影响：system 文本超文档承诺，超预算表现为上游报错、不是假成功，无数据风险。建议（不阻塞）：给 name/nextTitle 加上限（如 60/200）。另注：当前上限组合下「减少条目/压缩约定」两级实际不可达（安全网死分支，非缺陷）。
2. **低｜同类过期注释残留**：`apps/web/src/services/courses-store.ts:6` 仍写「聊天侧尚未携带课程标记」。
3. **低｜冻结元数据错误**：`FROZEN-CANDIDATE.json` 的 `candidateFullSha`/`candidateParent` 描述的是 r1；正确 full sha `701d391bde0d1b2a3e3a97e81b2248182378b3d9`、父 `9d966c3`。
4. **低｜凭证口径不准（并更正 r1 误判）**：`apps/api/.env` 存在 1 条非空值 `ZQKY_API_KEY_<connectionId>`，与根 `.local-data/model-config.json` 中唯一连接 id 匹配，解析路径一致 → 「无可用凭证」不成立，正确表述为「未外呼、未验证凭证有效性」。A1 更正其 r1 报告中「`.local-data/` 不存在」的误判。
5. **nit｜e2e 时序硬编码**：新用例固定 `waitForTimeout(20)`，慢机器上可能失去判别力（真正的修复是代码级守卫，用例只是回归网）。
6. **nit｜构建目录卫生**：`.next/dev/**` 保留旧文案 chunk（不被 `next start` 服务）。
7. **残余风险（低）**：守卫保持到卸载意味着「保存成功但导航始终未完成」时按钮停在「正在创建…」无自愈（刷新即恢复），代码注释已声明取舍。
