## 04 必须遵守的统一规范

- 先读根、前端/后端及所属模块 AGENTS.md；现状以 CURRENT_STATUS 与代码核对。仅在分配目录开发，公共文件通过 P1 集成。
- 前端路由薄、features 承载业务、services 负责请求；共享类型只用 contracts。客户端生命周期内使用浏览器能力，实例状态通过注入，禁止生产伪成功。
- 唯一业务后端为 FastAPI；路由→服务→仓储分层。API 外部字段 camelCase，Python 内部 snake_case，显式 DTO 映射；禁止 raw DB 行直接出接口。
- 前端只经 api-client 与 /api/v1 同源代理访问；错误不降为空库。全站样式复用字体/颜色 token，模块类有作用域，保持现有 /chat 视觉基准。
- SQL 参数化且经 core/sqlite.py；事务内不解析文件、不调用模型/网络。跨库引用通过只读查询接口核验，不冒充真实外键。正式修订不可变。
- 分数使用百分之一分整数 scoreUnits/maxScoreUnits，0 是有效得分，空白/缺考/免考为显式状态；不做自动改卷、评分点、知识点失分分摊或概率预测。
- 模型统一 resolve_chat_model；点击时冻结模型和依据，AI 只返回待审核建议，失败保留草稿。API 密钥只存后端，学生标识不发到生成模型。
- 自己的独立工作目录和 codex/Px-* 分支；共享目录不切分支、不批量暂存。依赖变更申请 P1，不升级无关框架。已知旧失败和新回归分开记录。
