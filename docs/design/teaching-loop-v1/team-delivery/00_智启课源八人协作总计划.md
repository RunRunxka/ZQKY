# 智启课源八人协作实施计划

版本 1.0   分工 代码规范 API 对接 阶段计划 验收标准

## 01 项目基线和交付目标

本计划用于向 8 名员工下发智启课源教学闭环建设任务。采用前后端配对与独立测试，由 P1 统一接口、共享代码和集成。人员以 P1 至 P8 编号，正式下发时填入姓名。

代码基线：本地 main 分支 301fc356493db21d187ab85f32fd49dfffdc51ef，核查日期 2026-09-30。产品源码与 main 无差异；docs/PLAN.md 有用户未提交修改，docs/design 为本次新增设计。没有拉取远端，不能据此宣称已核对 GitHub 最新提交。

| 模块 | 当前代码事实 | 本轮增量 |
| --- | --- | --- |
| 教材与 RAG | SQLite 教材目录、本机 Qdrant、混合检索、证据和可恢复定位 | 复用受控教材依据；不重写检索引擎 |
| 独立题库 | 导入、拆分合并、人工校对、AI 建议、幂等确认、题目修订 | 正式知识点关联、筛题、练习和回流 |
| 教案工作台 | 前端编辑、预览、规则填充、草稿、Word、PDF 打印 | 后台版本、学情依据、真实 AI 建议与审核 |
| 学情链路 | 班级、原卷小题、得分导入、学情服务尚未实现 | 按教师已给分成绩建立可追溯报告 |
| 模型管理 | 多供应商连接与共享 resolve_chat_model | 复用；不另造模型配置系统 |

### 首版必须坚持的规则

- 知识点独立建库，题目多对多关联；教材可作为依据，不是归类必经父级。
- 相关小题任意失分即列本次需巩固；缺考和空白不当零分；综合题的具体错因由教师确认。
- 系统接收已给分成绩，不改卷，不拆评分点，不训练掌握度模型。AI 调整先建议再审核。

排期假设：8 人全职、40 个工作日；不是固定日历承诺。第 1 周根据技能、试点原卷复杂度及现有回归基线重新估算，未通过阶段验收不按日历自动进入下一阶段。

## 03 统一代码规范

### 前端规范

- 前端路由薄、features 承载业务、services 负责请求；共享类型只用 contracts。客户端生命周期内使用浏览器能力，实例状态通过注入，禁止生产伪成功。
- 唯一业务后端为 FastAPI；路由→服务→仓储分层。API 外部字段 camelCase，Python 内部 snake_case，显式 DTO 映射；禁止 raw DB 行直接出接口。
- 前端只经 api-client 与 /api/v1 同源代理访问；错误不降为空库。全站样式复用字体/颜色 token，模块类有作用域，保持现有 /chat 视觉基准。
- 组件 PascalCase，hook 用 use 前缀，服务/类型文件沿现有 kebab-case；异步调用支持 AbortSignal，迟到响应核对 entityId 与 revision 后再应用。
- TypeScript strict，不增加未解释的 any 或 @ts-ignore；测试替身放测试目录。UI 提供空态、加载、异常、重试、取消、保存和冲突状态。
- 1440×900、1920×1080、390×844 分别验证；表格可横向滚动，手机保留证据与错误入口；键盘焦点、减少动画、打印样式按现有约定。

### 后端规范

- Python 类型注解覆盖服务和仓储公开方法；Pydantic extra=forbid；校验错误沿用 AppError 与统一错误处理，不回显成绩文件内容。
- SQL 参数化且经 core/sqlite.py；事务内不解析文件、不调用模型/网络。跨库引用通过只读查询接口核验，不冒充真实外键。正式修订不可变。
- 同步解析/SQL 用有界线程或后台任务，避免阻塞 async 路由；连接的线程归属明确，不把同一 sqlite3.Connection 跨线程共享。
- 同库提交单事务；跨库只做身份和版本核验加快照，不提供分布式事务假象。归档历史实体而不是删除历史修订。

### 工具和提交纪律

- 根 npm workspace 与 package-lock 是前端依赖权威；后端 uv、pyproject 与 uv.lock。采用现有 Prettier/ESLint，不新增第二套格式器。
- 前端 format:check/typecheck/lint/单测；后端 pytest。PR 小批提交，标题注明 Px 和用户行为，描述含正常/失败证据、兼容、not_run。
- 每位员工独立 clone/worktree 和测试数据目录；目标集成分支启动时由 P1 确认，沿仓库现有约定，不让员工直接写 main。推送/发布另按管理者流程。

| 计分小题 PaperItem | itemId、parentItemId、displayNumber、isScored、maxScoreUnits、content、knowledgeLinks、sourceLocator；计分项须叶子 |
| 学生分数 StudentItemScore | participantId、itemId、status=recorded/missing/absent/exempt；scoreUnits 在 recorded 时整数，其余 null |
| 报告 KnowledgeObservation | knowledgePointId、observation、validItemCount、lossItemCount、missingItemCount、evidence；counts 由固定小题事实生成 |
| 编辑 revision 和修订 ID | revision 是乐观锁整数；paperRevisionId/scoreRevisionId/questionRevisionId 等是不可变 UUID；不能混用 |
| WorkflowJob | jobId、revision、kind、state、stage、progress、attempt、inputHash、result/null、error/null、createdAt、updatedAt；不含密钥和模型原始日志 |
| 新增列表 | items、total、offset、limit；默认20，最多200，排序字段 allowlist；已有 questions 包装不变 |

### 学情显示状态按顺序判断

| 条件 | observation 和显示 |
| --- | --- |
| 至少一条有效成绩失分 | needs_consolidation 本次需巩固；存在未录另提示 |
| 没有相关有效成绩 | no_evidence 暂无有效依据 |
| 已有有效成绩全满分，但仍有无效/缺失依据 | incomplete 资料不全 |
| 所有相关小题都有有效成绩且全部满分 | full_credit 本次相关题均满分 |

时间戳 UTC ISO8601，显示转本地时间；日期 date 用 YYYY-MM-DD。学号字符串保留前导零。分数 Decimal 校验≤2 位小数，乘100后整数存储；不用浮点比较或静默四舍五入。新接口内部默认 UUID，不能把姓名、题号当主键。

内容块模型 W1 冻结为 paragraph/table/formula/image/sharedStem。公式原始 OMML 和可展示投影、配图受管 assetId 均保留；无法可靠转换需可见告警且不允许静默确认丢失内容。内容模型由 P3 提案，P1 冻结，P2/P5/P6/P7 复用。

## 10 对接样例和错误处理

### 确认成绩后发起分析

```text
POST /api/v1/assessments/as-01/analysis-runs
{
  "submissionId": "analysis-20260930-001",
  "scoreRevisionId": "score-r1",
  "participantIds": ["participant-01"],
  "ruleCode": "any_loss_v1"
}
202 {"jobId":"job-01","state":"queued","revision":0,
     "kind":"analysis","result":null}
```

上方仅节选响应，完整 WorkflowJob 还含第09节字段。任务成功 result={"runId":"run-01"}。前端随后获取 run 和对应学生/班级报告，不从任务正文猜测学情。

### 失分证据必须能定位

```text
{"knowledgePointId":"kp-monotonic",
 "observation":"needs_consolidation",
 "evidence":[{"itemId":"item-16-1","displayNumber":"16(1)",
 "status":"recorded","scoreUnits":300,"maxScoreUnits":500,
 "isLoss":true,"sourceLocator":{"kind":"docx","blockStart":18}}]}
```

| 情况 | HTTP 和前端动作 |
| --- | --- |
| 实体不存在/已归档不允许新引用 | 404 NOT_FOUND 或409 ENTITY_ARCHIVED；保留表单 |
| expectedRevision 过时、建议依据过时 | 409 REVISION_CONFLICT/PROPOSAL_STALE；展示新旧差异，不自动覆盖 |
| 同 submissionId 不同请求 | 409 IDEMPOTENCY_CONFLICT；同键同请求返回原结果 |
| 映射、负分、超满分、公式无缓存 | 422 INVALID_MAPPING/INVALID_SCORE/FORMULA_VALUE_MISSING；定位问题 |
| 模型/存储不可用，功能未实现 | 503 SERVICE_UNAVAILABLE/MODEL_NOT_CONFIGURED；501 FEATURE_NOT_IMPLEMENTED |
| 正常 HTTP 的业务失败 | 现有题库 ConfirmResult.failures 非空视为未确认；新版确认统一422且零正式写入 |

错误信封继续 code/message/requestId/retryable/details；详情只放脱敏可展示字段。ApiError 当前不保留 details，P1 做向后兼容扩展供导入界面显示逐格问题；文件下载建立专用 blob 请求，不用 apiRequest 的 JSON 分支。

## 11 API 冻结联调和并发协议

- D1 每个领域后端提交 endpoint 清单、Pydantic DTO、字段说明、成功/空态/冲突样例；配对前端逐字段确认。P1 对 enum、camelCase、分值、ID 和版本语义审查。
- D3 前冻结拟定契约为 v1.0：P1 保存脱敏 OpenAPI 和 fixtures，共享 TS 类型按同一 schema 镜像；至少校验字段、可空、enum、请求必填和额外字段。未注册路由的设计仍为拟定，不放进正式 API.md 已实现表。
- D4 至 D5 运行 schema/fixture 契约检查：Pydantic 可解析全部合法样例，未知字段/缺字段应失败；TS 客户端捕获409/422/503，页面错误不转成空库。
- W2 起每个配对组至少隔日联调一次；以真实 HTTP + 临时 SQLite 替换 fixture；联调发现差异按契约缺陷记录，不能两边各自加兼容猜测。
- 变更单写 endpoint、旧/新字段、消费者、迁移和测试；兼容新增由 P1 合并，破坏性变更提高契约版本并同步两端，保留旧夹具用于兼容验收。

### 确认和应用的并发顺序

前端编辑持 revision；确认提交 submissionId 和期望版本。后端 canonical JSON 计算 requestHash，在同库事务内核对 revision/幂等、校验引用和写入快照，提交后返回。相同键同载荷重放原结果，不同载荷409。跨库核验采用知识点/题目不可变修订，记录名称/学科快照；不在 SQL 事务中调用模型。

AI 建议绑定 baseRevision、analysisRunId、paper/score/knowledge/教材证据和模型指纹。教师在生成期间编辑，旧建议可查看但不能直接应用；需重新生成。模型配置改变后重试要求明示，不能把新模型当原任务静默继续。

| 提供方 | 消费者 | 接口约定 |
| --- | --- | --- |
| P2 KnowledgeQuery | P3/P4/P2练习 | batchGetConfirmedRefs(ids)；同学科/修订核验、无隐式新建 |

## 12 可复算的学情验收数据

P8 从合成矩阵与至少3份脱敏真实 DOCX 组织试点；每份由教师标定题号、计分叶子、满分、知识点、公式和配图。原件只读，解析清单逐项对照；原文完整不等于自动拆题100%正确，拆题允许人工纠正。

| 场景 | 输入 | 必须结果 |
| --- | --- | --- |
| 同知识点一题失分 | K1关联5题3/5与12(1)4/4 | K1 needs_consolidation；保留2条事实依据 |
| 综合题失分 | 16题关联K1/K2，8/10 | K1/K2同时需巩固；具体错因需确认，无分值分摊 |
| 真实零分 | K3一题0/5 recorded | 需巩固，0不能当空白 |
| 只有无效依据 | K4题 blank、absent、exempt | no_evidence；scoreUnits null，无失分事实 |
| 满分但部分缺失 | K5一题5/5，一题missing | incomplete；不能宣称已掌握 |
| 全部满分 | K6两题均满分 | full_credit；显示本次相关题均满分 |
| 多班同名和前导零 | 同名张同学、学号0012/012 | 不自动合并；学号文本保真 |
| 重复点击和修正 | 相同 submissionId；得分r1→r2 | 一次确认；旧报告仍绑定r1 |
| 计分容器 | 16总题干+16(1)/16(2) | 总题干不录分，不重复加总 |
| 班级人数 | 一人3个薄弱知识点 | 各知识点去重人数；不把人数相加当班级人数 |

P4、P8 各自从原始事实复算结果；不得用同一个实现函数作为预期生成器。班级比例必须标明本知识点有效参测人数与无有效依据人数，不把未录入者算作失分。旧设计33项内存验证可迁为约束用例，但不能冒充实际服务和文件导入验收。
