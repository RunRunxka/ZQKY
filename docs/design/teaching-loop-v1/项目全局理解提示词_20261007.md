1. 这个项目是什么
═══════════════════════════════════════════════════════════════════

面向教师的 AI 教学工作台。2026-09-29 起的主线是**教材 RAG + 教学闭环**：
教师把「原卷 + 小题得分」变成「学情报告 → 针对性练习 → 新成绩回流 → 学情驱动教案」，
系统只做规则的、可解释的、可审计的事，AI 只出**待教师选择的建议**。

已有真实能力（后端 + 前端都实现）：
  学习问答（真实三协议 SSE）· 模型连接与目录管理 · 教材资料库与 RAG（目录/修订/索引代/混合检索/

  施测 · 小题成绩（XLSX/CSV，四态）· 固定学情报告 · 针对性练习与回流 · 教案（规则填充/编辑/草稿恢复/
  后台保存与历史/学情驱动 AI 调整/Word 与 PDF 导出）。

仍是**显式本地模拟**：书籍生成。仍是**规划页**：协同写作、沉浸阅读、学习空间、智能组卷、模板中心

4. 领域模型与口径红线（教学闭环）
═══════════════════════════════════════════════════════════════════

链路：知识点 → 名单/班级 → 原卷(DOCX) → 施测 → 小题成绩 → 学情报告 → 针对性练习 → 回流 → 教案。

关键规则（改代码前必须理解，违反即视为缺陷）：
· 知识点：编码同学科内唯一；名称只存在修订表；AI 候选**只进待确认批次**，不自动发布；
  「教材读不到」≠「没有依据」（应报 TEXTBOOK_EVIDENCE_UNAVAILABLE）。
· 名单：学号按文本保留前导零；名单里未出现的旧学生**不退班**；转班保留旧归属历史。
· 原卷：只有**计分叶**承载分值，父题为容器；满分标记取首个匹配，**找不到就阻断而不是猜**；
  「一、选择题（共40分）」这类分节标题是**结构边界**（不进上一题题干、其"共 N 分"不当上一题满分，
  自己落 unassigned 交教师处理）；独立成段的「（1）」及其后续正文归完整子题路径（如 15(1)）；
  确认闸门：任何阻断问题或未归属块存在 → 422 逐条列出；**已确认修订不可变**，改则新建修订。
· 施测：只能选已确认原卷修订；参测名单冻结为快照；施测日期早于名单归属起始日时要求
  显式确认班级 + 依据（classConfirmed/classConfirmationNote），**服务端不自动改归属**。
· 成绩：四态严格区分（有效 / 空白 / 缺考 / 免考）；**0 是有效分，空白不补 0**；
  确认请求带 submissionId 幂等（丢响应可原样重放）；确认后的成绩修订不可变。
· 学情：`any_loss_v1` —— 任一关联小题有效得分低于满分 = 本次需巩固；
  输出的是**本次需巩固比例，不是掌握率**；报告是后台任务，含班级/学生/题目证据/教师备注四个视图。
· 练习：只从正式题库选题，缺口不放宽约束；复核计分结构后独立审核生成只读修订；
  导出学生 DOCX / 教师 DOCX / 成绩模板 XLSX（模板必须在本练习转成施测之后生成）。
· 教案：AI 生成走「教师明确选择的固定报告 + 知识点 + 核验教材切片 + 模型档案」；
  候选**逐字段**展示差异，教师勾选才采用；教师标题/课时/课型/反思受保护；
  另有**不连模型**的「要求填充（规则）」路径。

绝不打破的红线：不自动评分、不补零、不反推、不预测掌握概率；缺就报缺（不伪造成功、不返回空结果）；
AI 一律只建议；已确认数据不可变、修正是新版本并留审计。

· 单测在 Node 26 下必须 `NODE_OPTIONS=--no-experimental-webstorage`，否则 jsdom localStorage 大量假失败。

  临时实验请改用别的端口，避开 5173/5174。
· 别在别人（或另一个会话）跑着服务/测试时抢占端口，先 `netstat -ano | grep LISTENING` 看一眼。

6. 模型口径（2026-10-06 起，用户裁定，已实现）
═══════════════════════════════════════════════════════════════════

· **教案生成只使用云端模型**：档案落在注册表 `is_local` 供应商（Ollama/vLLM/LM Studio/llama.cpp）时，
  后端 422 `LESSON_MODEL_NOT_CLOUD` 且**不发任何模型请求**；前端「模型档案」下拉只列云端档案，
  未显式选择时自动选中「全局默认问答模型」（defaultChatProfileId）。
· **RAG 知识点概括只认「全局默认问答模型」且必须云端**：未配置默认模型 / 默认是本机部署 →
  503 `RAG_SUMMARY_UNAVAILABLE`（问答侧转 partial 并保留教材原文，**绝不回退本机**）；
  `status()/probe()` 是**配置级检查**（不向云端发推理调用），"可用"只代表配置就绪。
· 传输层按档案协议调用（openai-chat / openai-responses / anthropic-messages 均可）；
  提示词预算由档案 `contextTokens`（未声明用 8192）与输出上限（夹 256–2048）推导，
  并与 6000 字符证据上限取较小者。
· 视图字段：连接的 `isLocal`、档案的 `isDefault`（`/model-connections`、`/model-profiles`、`/model-catalog`）。
· 本机模型仍可用于问答等其它路径（那是设计，不是遗漏）。

7. 工程纪律（AGENTS.md 之外仍要记住的）
═══════════════════════════════════════════════════════════════════

· 路由薄、业务厚；跨模块类型进 contracts/；导航/主题/服务定义各只维护一份。
· 能力注入：模块顶层不读 window/document/localStorage；浏览器能力放客户端生命周期内。
· **单一后端**：不要用 Next Route Handlers 起第二套业务后端。
· 依赖：用根 workspace 与锁文件；不顺手升级框架、不换包管理器。
· 样式：全站共用 globals.css 变量层；space.css 是知识库/书籍/课程等内容页的共享基础样式；
  模块样式以页面修饰类起头，不污染共享层。
· 文档：进度只写 CURRENT_STATUS；目标与稳定决定只写 PROJECT_GUIDE；不动原 Word 模板与只读参考目录。
· Git：检查 → 小批改动 → 验证 → **明确范围提交**；不自动推送/部署、不改全局 Git 身份、不切共享分支；
  撤销明确提交优先 `git revert`，不用 `reset --hard`/`clean -fd`。
· 协作：可能有其他会话/智能体在同一工作区（例如 scripts/teaching-quality/** 与部分 docs）。
  动手前先 `git status` + `git log` 看现场；**不碰别人的改动**、不批量暂存、不清理未知数据。
· 提交范围：用户可能只允许提交"项目代码"（docs/qa 证据、其他会话的文件不要带上），
  提交前用 `git diff --cached --stat` 自查。

8. 测试与验收纪律
═══════════════════════════════════════════════════════════════════

· 提交前 `npm.cmd run check`；路由/布局/保存/导出改动另跑 `npm.cmd run test:e2e`（先 build）。
· 只跑与变更相关且有意义的场景；**未执行的检查写「未执行」+ 原因，不写「应当通过」**。
· 严格区分：真实服务 / 本地规则 / 显式模拟 / 规划状态；**构建成功 ≠ 业务或视觉验收通过**。
· 不把"跳过即 PASS"当证据（历史上曾因此抓到假证据）；测试替身必须**与生产同一条调用路径**
  （例如用真实 provider + MockTransport，而不是重写一份逻辑）。
· 修完要**自写反例复验**；重要声明（"已修好/可用"）要有可复核的命令与输出，必要时请独立验收者复核。
· 报告事实边界：没外呼就写"未外呼/未验证"，不写"无可用凭证"这类推测性归因。

## 附：怎么用这段提示词

| 场景 | 做法 |
| --- | --- |
| 新会话接手 | 整段粘贴，末尾替换成本批任务；如果只是"熟悉项目"，把最后一行删掉即可 |
