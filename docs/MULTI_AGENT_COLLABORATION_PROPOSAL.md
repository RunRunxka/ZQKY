# 多智能体协作任务模板

更新：2026-09-12。本文提供可复用任务卡、结果卡、资源分配格式和外部团队启动提示词。实际规则以根 `AGENTS.md` 为准，当前任务需求、进度、候选 SHA、缺陷和下一动作只看 [STATUS](STATUS.md)。旧完整提案与演练可从 Git 提交 `6e3f642` 追溯，不作为当前项目指令。

## 角色

| 角色 | 责任 | 默认写权限 |
| --- | --- | --- |
| 总控 | 拆分任务、确定依赖和候选、分配资源、集成、更新权威文档、最终 Git | 公共契约、权威文档、矩阵、锁文件、Git |
| 取证 | 核对固定参考、源码、交互状态和验收参数 | 只读；证据写入专属产物目录时须由总控分配 |
| 实现 | 在有限文件范围完成一个行为闭环并做相关自检 | 任务卡列出的文件 |
| 验收 | 对稳定候选独立复现、检查失败路径和边界 | 默认只读；不得边验边修 |

角色是职责，不要求固定平台或常驻实例。总控不得用智能体口头结论代替实际文件、命令结果和候选 SHA。

## 工作流

1. 总控先读取当前规则、STATUS、三矩阵和实际源码，确认用户本次授权。
2. 取证只回答有限问题：参考入口、状态机、数据边界、动画参数和可复现验收点。
3. 总控冻结契约和任务版本，再分配唯一文件写入者、测试端口、浏览器数据、构建目录和报告目录。
4. 实现者交付 `ready_for_review`，不得自行把模块标为已验收。
5. 总控固定待验候选；验收者记录 `pass / fail / not_run`，失败必须给触发条件与证据。
6. 总控决定 `pass / needs_revision / blocked`，更新 STATUS 和对应矩阵，显式暂存并提交。

## 写入与运行资源

- 同一文件同一时段只有一个写入者。公共组件、契约、权威文档、矩阵和锁文件默认由总控写。
- 共享工作区不切分支、不批量暂存、不清理未知文件、不回退其他人的修改。
- 测试端口、浏览器会话、测试数据、截图目录和 build 输出也必须有所有者；文件不冲突不代表运行资源不冲突。
- 验收期间候选保持不变。需要修复时结束该验收版本，升级任务版本后重新提交候选。
- 只通过 build、存在路由、存在组件或存在截图，均不足以将功能、视觉、动画或真实服务状态标为通过。

## 智启课源专用门槛

- 全站默认主页和视觉基准是当前学习问答 `/chat`，保留智启课源品牌和蓝色主题。
- 每个页面批次分别报告功能状态与学习问答视觉状态；业务工作区不强制套用聊天 236px 中栏或 912px 内容宽度。
- 主聊天生产只允许真实服务；测试替身留在测试目录。其他模块的显式模拟须完整保留加载、失败、取消、重试、恢复、保存和跨页状态。
- 真实供应商、隔离上游、本地规则、显式模拟和纯前端验收分别记录。
- 浏览器自动化使用隔离数据和 5174，不读取或清空用户在 5173 的草稿。

## 交接要求

交接只更新 [STATUS](STATUS.md)、对应三矩阵和必要契约文档。NEXT_SESSION_START 只保留接手方法，不复制计划；旧 TASKS、HANDOFF 和长提示词不再新建。提交前检查 `git diff --cached --check`、暂存范围、凭证和生成产物；不自动推送或部署。

## 可复制的外部团队提示词

把下面“队长启动提示词”交给你选用的其他 Agent 工具。角色文本用于工具的子任务/角色配置；若工具没有可靠委派、文件隔离和结果回传能力，由一个实现者串行执行，取证和验收保持只读。`AGENTS.md` 本身不会创建智能体或强制锁文件。任务的实时版本、详细需求和权限以 STATUS 第6节为准，本文不维护第二份计划。

### 取证角色提示词

```text
你是只读取证者。只执行队长发给你的有版本任务卡，不自行扩大供应商/业务范围。
逐项核对固定DeepTutor的注册元数据、实际工厂路由、请求参数、认证与发现实现及相关测试。
输出：参考路径与行号、目标已有实现、缺口、可复用点、不能照搬的配置/凭证边界、建议验收场景。
发现“注册表声明”和“实际适配器”不一致时分别列证据，不凭名称猜支持。
不修改源码、权威MD、锁文件或Git；报告仅写队长分配的专属产物目录。不会访问真实密钥文件。
```

### 实现角色提示词

```text
你是有限范围实现者。开工前回报任务ID/版本、合同版本、候选及你独占的文件和运行资源。
只实现任务卡定义的行为闭环；共享契约变化先向队长提交最小建议，不能自行修改归其他人负责的文件。
沿用现有接口、错误信封、SSE、revision和凭证存储，保留旧ID及配置；无服务能力不能返回假成功。
用临时配置/内存凭证完成相关自检，保留首败并验证修复；真实服务与模拟上游证据分开。
完成时提交ready_for_review结果卡，不自行宣布已验收、不提交Git。
收到停止/交验后停止写源码与共享产物，回报未完成事项、服务进程及资源释放情况。
```
