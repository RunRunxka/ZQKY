# 多智能体协作规范（可复用任务卡与角色模板）

更新：2026-10-13。**本文是协作方法文档，不是计划文档**：项目目标与稳定决定看
[PROJECT_GUIDE.md](PROJECT_GUIDE.md)，进度/台账/当前任务看 [CURRENT_STATUS.md](CURRENT_STATUS.md)，
硬性规则以根 [AGENTS.md](../AGENTS.md) 为准。三者冲突时以 AGENTS.md 与 CURRENT_STATUS 为准。

本文适用于「一个总控 + 若干有界实现/取证/验收智能体共享同一工作区」的批次作业；
单人串行开发时同样按任务卡/结果卡的**格式**留证据，只是角色合并（自检与独立验收必须分别记录）。

## 1. 角色

| 角色 | 责任 | 默认写权限 |
| --- | --- | --- |
| 总控 | 拆分任务、定依赖与文件归属、集成、更新权威文档、最终 Git | 公共契约、权威文档、验收矩阵、锁文件、Git |
| 取证 | 只回答任务卡里的有限问题（参考入口、状态机、数据边界、可复现验收点） | 只读；证据写入任务卡指定的产物目录 |
| 实现 | 在有限文件范围内完成一个行为闭环并做相关自检 | 任务卡列出的文件 |
| 独立验收 | 对稳定候选独立复现、检查失败路径与边界 | 默认只读；不得边验边改 |

角色是职责，不要求固定平台或常驻实例。**总控不得用智能体的口头结论代替文件、命令结果与提交 SHA。**

本机（开发机）落地的 Agent 类型与角色的对应：`RAG-build` = 有界实现（后端/数据/服务）、
`RAG-front` = 有界前端实现、`RAG-accptance` = 独立验收（只读、不边验边修）、`Explore` = 只读取证/检索、
`general-purpose` = 总控自用的通用执行。这些定义在 `.zcode/agents/*.md`（**机器本地配置，已 gitignore**，
不属于仓库源文件）；换机器或换工具时按 §3/§4 的模板重建即可，协作契约不变。

## 2. 工作流

1. 总控先读 AGENTS.md、CURRENT_STATUS、PROJECT_GUIDE 与实际源码，确认本次用户授权；
   已交付批次只作基线，不重复执行。
2. 取证只回答有限问题；视觉/真实能力不能只凭组件名或类型定义断言。
3. 总控定任务版本、共享接口与唯一文件/运行资源负责人；共享契约先由单一负责人定稿。
4. 实现者交付 `ready_for_review`，**不得自行把模块标为已验收**。
5. 总控固定待验候选（SHA 或差异标识）；验收者逐项记 `pass / fail / not_run`，
   失败必须给最小复现与证据。
6. 总控裁定 `pass / needs_revision / blocked`，更新 CURRENT_STATUS 与该批证据；
   只有本次明确授权时才执行 Git 提交。

## 5. 写入与运行资源

- **同一文件同一时段只有一个写入者**；公共组件、契约、权威文档、矩阵与锁文件默认由总控写。
- 共享工作区**不切分支、不批量暂存、不清理未知文件、不回退他人改动**。
- 测试端口、浏览器会话、测试数据、截图目录与 build 输出也必须指定所有者：
  文件不冲突不代表运行资源不冲突。
- 验收期间候选保持不变；需要修复时结束该验收版本，升级任务版本后重新提交候选。
- 只通过 build、存在路由、存在组件或存在截图，均不足以把功能/视觉/真实服务标为通过。
### 5.1 真机脚本与探针的安全硬规则（2026-10-13 两次误删用户数据后追加）

对**真实数据根**运行任何脚本（HTTP/浏览器/直接 SQL）前，逐条满足：

1. **只碰自己刚创建的对象**：破坏性动作（DELETE/PATCH/DELETE 类按钮、确认弹窗）的目标 id
   必须来自**本次脚本自己的创建响应**，并在点击/请求前断言 `target === selfCreatedId`，
   不等就中止——不是"日志里看起来对"，是代码里的硬断言。
2. **禁用位置选择器做破坏性动作**：不许用"第一行/最后一行"之类的定位去点删除；
   只能用自建返回值构造的 testid / URL。
3. **不自动接受确认弹窗**：`window.confirm` 一律先断言文本与目标对象，再接受；
   批量弹窗（一次影响多对象）直接跳过。
4. **纯读不能走写方法**：想观察 409 守卫就用**只读端点或直接查库**，
   不要用 DELETE 去"看会不会被拦"——守卫条件随数据变化，删得掉就真删了。
5. **结束态核对**：脚本收尾必须回读用户数据基线（班级/学生/试卷/成绩/教案计数），
   发现变化立即停手并在结果卡里报告。
6. **先快照后动手**：对真实库先做只读字节拷贝到 `_work/`（保全取证材料），再跑脚本。


## 6. 本项目专用门槛

- 全站默认主页与视觉基准是学习问答 `/chat`（品牌蓝主题不变）；业务页由
  `ModuleWorkspaceShell` 统一提供壳与滚动，页面裸渲染。
- **LangChain + LangGraph 是架构硬性**：所有 LLM 调用经 `resolve_agent_chat_model` +
  `services/llm/`；业务代码禁止直连供应商 SDK（门禁 `tests/test_no_raw_sdk_imports.py`）。
- **红线**：AI 输出只进候选、教师确认才落库；学生姓名/学号不进模型（学情一律代称）；
  凭证只存后端 `apps/api/.env`，不进前端、源码、日志、截图、测试样本。
- **删除即删除**（2026-10-13 用户裁定）：舍弃归档入口、只留删除；引用按
  「自有行级联 / 下游产物级联 / 可空引用置空 / 不可拆 409 逐项列出」分流；
  成绩链所有者是施测——其它实体的删除永不静默销毁学生成绩。清单见 [API.md](API.md)。
- 主聊天生产只允许真实服务；其他模块的显式模拟必须完整保留加载、失败、取消、重试、
  恢复、保存与跨页状态，且不得冒充真实。
- 真机验收用真实后端（8000）+ 真实数据根 + 真实前端（5173）；**自建数据自建自删，
  不覆盖用户数据**（脚本以命名空间标记，结束后核对用户数据回到基线）。
- 自动化浏览器使用系统 `msedge` 通道与测试端口（e2e 自起 5174），不读取或清空用户在 5173 的会话。

## 7. R0–R10 实践沉淀（本项目验证有效的做法）

1. **批次 = 一个行为闭环 + 独立门禁 + 显式路径提交**（R0…R10 的每一批都如此）：批次内先取证、
   再实现、再全量门禁，最后按范围提交；不做跨批「顺手改」。
2. **测试随批增长**：新能力必须带正/负用例；改写既有守卫语义时要同步改写断言它的用例，
   并在提交信息里说明语义变化（本仓库历史上多次如此：R5 施测、R9 收口、R10 删除语义）。
3. **门禁三件套**：`uv run python -m pytest`（后端）、`npm run check`（前端）、
   `npx playwright test`（e2e）；三者数字写进 CURRENT_STATUS 的证据段。
4. **真机证据分两层**：脚本化 HTTP 走查（建链→删链→`foreign_key_check`/`quick_check`）
   + 浏览器走查（用户看到的现象）；两者都要有可复现脚本（`_work/` 下，脚本名带批次号）。
5. **契约变更单一负责人**：`contracts/` 与 `schemas/` 由总控或其指定者一次改完，
   前后端在同批内对齐，避免「前端半成品等后端」的跨会话悬空。
6. **历史实现只从 tag 取**：`git show archive-full-v1-20261011:<path>`，不把旧文件捞回工作区。
7. **停点必留交接**：CURRENT_STATUS 写明已完成/未完成/现场状态/恢复顺序；未完成项要能被
   下一个会话直接接手（本仓库 R10 暂停—恢复即按此完成）。

## 8. 交接要求

- 更新 CURRENT_STATUS（进度、门禁数字、当前任务、下一动作、现场状态）与本批证据；
  长期决定写 PROJECT_GUIDE；接口契约写 API/ROUTES。
- **不新建重复的 TASKS/HANDOFF 入口**；需要提交时先核对本次授权，再检查
  `git diff --cached --check`、暂存范围、敏感数据与生成产物；**不自动推送或部署**。
- 保留历史首败与未验证范围；必要脱敏证据随 Git 保存，不能只依赖 `_work/`。

## 9. 可复制的提示词

### 9.1 新对话接手提示词（推荐直接使用）

```text
你接手「智启课源」（ZQKY）继续开发。工作目录 F:\ZQKY，分支 main（开始前用 `git log -1` 核对 HEAD）。
先不要改任何代码。

【第一步：读】AGENTS.md → docs/CURRENT_STATUS.md（顶部「当前状态」是权威）→ docs/PROJECT_GUIDE.md →
docs/README.md（索引）→ 本文件（docs/MULTI_AGENT_COLLABORATION_PROPOSAL.md）→ docs/API.md 相关小节 →
涉及模块的 AGENTS.md（如 apps/web/src/features/chat/AGENTS.md）。

【第二步：只向我报告，不改代码】
1) 项目形态与最近一批（R12 教案工作台）交付内容；
2) 门禁基线（后端 1946 / 前端 768 / e2e 17，以 CURRENT_STATUS 顶部为准）与你实际复跑的结果边界；
3) CURRENT_STATUS 的「当前任务/下一动作」是否有在途批次；有则给恢复顺序；
4) 你建议的下一批：需求一句话 + 实现方式 + 验收条件 + 涉及文件/运行资源，等我确认再动手。

【第三步：协作方式（确认后按此组织）】
- 你担任总控：拆任务、定文件归属、集成、最终 Git；同一文件同一时段只允许一个写入者。
- 有界实现用本机 Agent 类型 `RAG-build`（后端/数据/服务）与 `RAG-front`（前端 apps/web）；
  独立验收用 `RAG-accptance`（只读产品、不能边验边修）；只读取证/大范围搜索用 Explore。
  给每个 Agent 的任务卡必须写全：任务 ID/版本、起点 SHA、可写文件、禁止修改、验收条件、
  必须运行的命令、证据目录、结果卡格式（见本文件 §3/§4）。
- 契约（contracts/、schemas/）与权威文档、锁文件、Git 由你这个总控独占写；
  实现者只能改任务卡列出的文件，交付 ready_for_review 时停止写入。
- 候选固定后才验收；验收失败交实现者修，改完升级版本重新给候选，不用旧候选结论。
- 不并行写同一文件；不并行抢同一端口/数据根；真机验收自建数据自建自删。

【第四步：纪律与证据】
- 按批次给门禁三件套证据：`cd apps/api && uv run python -m pytest`、
  `NODE_OPTIONS=--no-experimental-webstorage npm.cmd run check`、`npx playwright test`（msedge 通道）；
  未执行的检查如实写「未执行」及原因，不写「应当通过」。
- 不切分支、不批量暂存、不推送；提交只在明确授权时按范围执行。
- 红线：AI 只进候选、教师确认才落库；学生姓名/学号不进模型；凭证只存后端 .env；
  LLM 一律经 LangChain/LangGraph（`resolve_agent_chat_model` + `services/llm/`）。
```

### 9.2 总控（批次负责人）

```text
你是本批总控。开工先读 AGENTS.md、docs/CURRENT_STATUS.md、docs/PROJECT_GUIDE.md 与相关源码，
核对用户本次授权与现场 `git log -1` / `git status --short`；已交付批次只作基线。
为每个子任务写完整任务卡（§3 模板：ID/版本/负责人/起点 SHA/可写文件/禁止修改/验收/必须运行/结果格式），
按角色派给本机 Agent 类型：RAG-build（后端/数据）、RAG-front（前端）、RAG-accptance（独立验收，只读）、
Explore（只读取证/检索）。共享契约、装配、导航、权威文档与 Git 由你独占写入。
候选固定后才验收；验收失败交实现者修复后升级版本重给候选，不使用旧候选结论。
集成后跑本批门禁三件套并把数字写进 STATUS；提交只在用户明确授权时按范围执行（不推送）。
最终回报：任务 ID、起点/实现 SHA、改动、保留的数据、各维度证据与 pass/fail/not_run、
未执行项与原因、剩余范围与资源释放。
```

### 9.3 取证（可用 Explore 或只读 general-purpose）

```text
你是只读取证者，只回答任务卡内的有限问题。核查固定参考、现有源码、交互/数据边界与验收场景，
给文件行号，区分事实、推断与未验证。视觉不能只看组件名，真实能力不能只看类型/注册表。
不改产品代码、权威文档、锁文件或 Git；证据只写任务卡指定目录，不读密钥，不抢占他人服务。
```

### 9.4 实现（本机 Agent 类型：RAG-build 后端 / RAG-front 前端）

```text
你是有界实现者：先核对任务 ID/版本、起点候选 SHA、接口契约与独占文件/运行资源。
只改任务卡列出的文件；完成任务卡的行为闭环，保持业务与数据兼容；共享契约/装配/导航交总控，不越界争改。
运行相关自检（后端 `uv run python -m pytest`、前端 vitest/typecheck/lint）并保留首败；
生产/模拟/测试替身分清，失败不假成功；未执行项写「未执行」及原因。
交付 ready_for_review 后停止写入：列差异、测试命令/退出码/证据、未完成、进程与资源；
不自行标整体验收、不提交 Git。
```

### 9.5 独立验收（本机 Agent 类型：RAG-accptance）

```text
你是独立验收者：先核对任务版本、稳定候选 SHA/差异、资源归属，并确认实现者已停止写入。
按验收条件自建或复核有意义场景，不复述实现者结论。视觉看真实页面与截图；动画看过渡/结束/中断；
数据任务验证持久化与失败恢复；异步任务检查迟到/取消/重试；真实服务与 fixture 分别记录；
真机验收用独立命名空间自建自删，不碰用户数据，结束后核对用户数据回到基线。
逐项输出 pass/fail/not_run、命令/退出码/证据与准确范围；只读产品，发现失败给最小复现交总控修。
```
