# 智启课源 AI 执行任务包

版本 1.0　编制日期 2026年9月4日

## 1 你如何使用这份任务包

先把《01_项目计划书》和《02_项目实现详细流程》交给参与开发的 AI。每次打开新对话，先粘贴下面的“通用上下文”，再粘贴一个任务。完成后根据验收条件检查，再交给下一位 AI。不要一次要求 AI 完成全部任务。

如果 AI 能直接访问本地仓库，让它读取真实文件；如果不能，把相关规范、目录树和当前文件打包上传。要求输出文件全文或可应用补丁，不要仅让它描述“应当如何实现”。不能运行命令的 AI 必须说明哪些检查没有执行。

对于你不熟悉的改动，先让独立的 AI 审查变更，再保存版本。开始时推荐串行；熟悉分支后，公共框架完成的不同页面可以并行。每个任务预期最好控制在半天到一天；超过范围就拆成更小任务。

## 2 每次对话的通用上下文

```text
你正在实现“智启课源”，一个中文优先的 AI 学习工作台。

产品目标：参考 DeepTutor v1.6.4 的 UI 和前端交互。
参考提交：e5f2d38c393497a57fda13209be55067c1740ca7。
采用独立前端加精简后端；我们自己的 /api/v1 不是原项目接口。
第一阶段交付完整 Mock 前端，之后接入上传资料、问答、引用、练习和笔记。

开始前读取：
1. 项目规划/01_项目计划书.md
2. 项目规划/02_项目实现详细流程.md
3. 当前仓库的 docs/TASKS.md、docs/DECISIONS.md、docs/HANDOFF.md（若已存在）
4. 与当前任务有关的源码、依赖锁文件和截图。

技术基线：Next.js App Router、React、TypeScript、Tailwind CSS 3.4。
自建后台采用 FastAPI、PostgreSQL、pgvector、Redis Worker。
具体依赖版本由初始化任务统一核实并锁定，之后不要自行升级。
风格基线：白色工作区、浅灰侧栏、蓝色交互色、220px 可折叠侧栏。
品牌使用“智启课源”，复用源码要记录原始路径和提交。

工作规则：
- 本次只完成下方指定任务。先简要列出修改文件和依赖，再开始实施。
- 以仓库规范为准；不要另外发明第二套路由、设计变量或 API。
- 页面通过 services 适配器读写数据；Mock 与真实 API 使用同一契约。
- 公共接口需要变更时，先指出影响范围并更新契约与调用方。
- 不覆盖无关改动，不把浏览器本地存储作为真实业务数据库。
- 不把密钥写进前端、源码、日志或交接文件。
- 不伪造连接成功、索引成功、模型调用、引用或测试结果。
- 未实现功能明确标记；真实环境不能失败后自动回落到 Mock。
- 完成后提供可运行代码、修改清单、实际验证、截图和未完成项。
- 更新 docs/HANDOFF.md，记录当前状态和下一任务。

现在请执行下面的单个任务。
```

如果最终改选“直接二次开发 DeepTutor”，必须整体改写通用上下文和后端任务；不要只替换项目名称就继续使用这套自建后台任务。

```text
任务 T01：建立可运行前端和公共布局。

只修改 apps/web、必要根配置、相关文档和锁文件。
核实可用运行环境，统一依赖版本和 npm 命令，提交锁文件。
根据 UI_SPEC 实现设计变量、AppShell、Sidebar、基础控件及 Mock 入口。
固定主导航路由；主题和折叠偏好可持久化。
首页先有真实布局，其他业务页提供有意义的空状态。
建立 services 的 mock 与 http 两种实现位置，不接模型密钥。

创建并运行 typecheck、lint、build 脚本，README 写明安装与启动命令。
分别检查 1440×900、1024×768、390×844。
输出首页、收起侧栏、手机抽屉三张实际截图。

验收：项目可以冷启动；深层 URL 刷新可用；没有页面横向溢出；

```

## 6 T02 实现聊天前端

```text
任务 T02：实现 /chat 与 /chat/[sessionId] 的 Mock 交互。

只修改聊天业务目录、services 中已约定的聊天适配器及相关规范。
复用公共组件，实现问候区、输入工具栏、模式和模型选择、消息列表、
活动抽屉、引用卡片、停止、重试、复制和保存笔记的操作入口。
Mock 事件使用确定性数据，覆盖正常、延迟、失败、中断和恢复。
不要让实际 UI 依赖一套与后端约定不同的定时器逻辑。

处理流式消息去重、中文输入法、向上阅读不自动跳底、长公式和代码块。
直接打开历史 URL 要恢复会话；离开页面后再返回不产生重复消息。
演示模式有明确标识，不显示虚假的供应商连接成功。

验收：空态、长会话、生成中、停止、错误及手机状态均有实际截图；
重复发送受控；引用操作可打开测试资料；状态与契约一致。
```

## 7 T03 实现知识中心和阅读前端

```text
任务 T03：先做知识中心，验收后再做阅读页。

知识中心包括列表、创建弹窗、详情、文件上传、状态、移除与预览。
上传阶段和解析索引阶段分开显示；失败文件可单独重试或移除。
用 Mock 覆盖全部成功、全部失败、部分可用和重新索引。
V0.2 不宣称已构建真实向量索引。

阅读页包括资料列表、PDF 或文本查看、页码或段落定位、右侧聊天、
书签和恢复阅读位置。手机用正文与问答标签切换。
如果使用固定 PDF 示例，保存合法可分享的测试文件和定位预期。
暂不支持的扫描资料明确说明原因。

验收：点击测试引用到正确页或段落；资料版本不匹配有提示；
大文件、错误文件和空列表不破坏页面；不会凭空补页码。
不要顺带实现多检索引擎、网页抓取或 OCR。
```

## 8 T04 实现学习空间 笔记和题库前端

```text
任务 T04：拆成历史、笔记、题库三个小提交，依次实现。

历史支持搜索、重命名、归档、恢复和重新进入会话。
笔记支持笔记本列表、Markdown 编辑、保存状态、来源和导出。
用 Mock 模拟保存失败与 revision 冲突，不弹成功提示掩盖错误。
题库支持筛选、收藏、作答和解析；题目版本与作答记录分别建模。
提交前的前端数据不应包含正确答案；通过答题 Mock 接口返回结果。
学习空间数量从 service 数据汇总，不能硬编码。

验收：从聊天保存的演示笔记能重新打开；归档会话可恢复；
单选和多选反馈遵循规则；手机可完成作答与保存；导出内容完整。
```

```text
任务 T05：每次只选择一个模块实施，不一次生成全部页面。

模块顺序：设置和账户 → 书本 → 学习路径 → 协同写作 → 伙伴 →
我的智能体 → 记忆。依据实现手册中各页面的状态和操作要求实现。
复用已有编辑器、聊天、卡片、弹窗和 TaskStatus，不能复制出第二套。
书本和学习路径包含创建向导；写作建议可以接受或拒绝；
智能体状态明确是演示；记忆记录能够编辑删除并显示来源。

每完成一个模块更新页面清单、截图和实际检查结果。
最后对全部主导航、深层链接和三种视口做一次连贯演示。

验收：计划中的前端页面全部可访问，主要按钮有可说明的行为；
演示模式清晰，错误态可触发；无主流程死路；不存在大量无意义占位卡。
```

## 10 T06 建立后台契约 数据库和认证

```text
任务 T06：按手册第 6 至 7 节建立 API 与持久化基础。

先整理 OpenAPI 和数据迁移，统一 ID、分页、错误格式和权限。
补齐首期页面必需的增删改查，再生成前端契约类型并更新 Mock。
实现登录、退出、当前用户与资源归属检查，公开注册默认关闭。
会话 Cookie 使用合适的 HttpOnly、Secure、SameSite 设置，
确定同源代理、CSRF 和 CORS 策略。
使用配置管理服务端密钥，不在返回结构或日志中泄露。

创建两个测试账号，验证 A 不能读取或修改 B 的业务资源。
提交可复现迁移和开发环境配置，README 给出空数据库启动方式。

验收：API 规范与实现一致；真实数据库可持久化；越权接口返回错误；
前端能切换真实认证，后端不可用时不自动变成演示用户。
```

## 11 T07 实现资料上传和检索

```text
任务 T07：用一个检索引擎打通资料摄取。

按手册实现上传、文件状态、Worker 解析、分块、嵌入和索引版本。
首期支持可提取文字的 PDF、TXT 和 Markdown，默认上限 20MB。
保留真实页码或段落 locator；按用户或知识库范围做文件去重。
活动索引只在新版本验证完成后切换，失败不破坏旧版本。
实现文件级失败、重试、取消、删除以及中途重启后的处理。

用固定教材和预期段落测试检索，不仅检查“有返回结果”。
记录每个问题前 5 条是否包含正确来源，分析未命中案例。
任何当前不支持的格式返回可理解错误，不用空字符串冒充解析成功。

验收：文件可预览、可检索、可删除；无重复分块；越权不可检索；
失败任务可恢复或明确失败；索引版本与嵌入维度一致。
```

## 12 T08 接入一个模型和事件流

```text
任务 T08：先只接一个供应商的真实文本模型。

实现模型适配接口、能力配置、最小连接测试、用量和脱敏错误。
密钥只在服务端；用户只能选择允许的 model_profile。
按契约 POST 创建 turn，GET SSE 订阅事件，支持快照与序号续传。
保存部分输出和终态，实现取消请求和服务端确认的区别。
client_request_id 在网络重试中防止重复生成。
流断开不能自动重新提交；发生部分输出失败时不拼接另一个模型结果。

实测正常输出、错误凭证、超时、限流、断线、刷新和取消。
输出时延与用量来源，未返回用量时标记未知。

验收：真实模型调用可复查；刷新不丢消息；重连无重复字块；
任务终态可信；浏览器和日志里没有密钥。
```

## 13 T09 联调问答 引用与阅读

```text
任务 T09：把 T07 的检索和 T08 的生成接入聊天与阅读页面。

服务端校验选中知识库和资料版本，检索结果分配 source_id，
把原文及来源映射传给模型。返回引用只能使用实际存在的 source_id。
资料依据不足时明确提示，不生成不存在的页码和链接。
引用跳转检查 doc_id、version 和 locator，删除资料后友好报错。
阅读会话绑定当前资料，正文位置可保存恢复。

运行 30 个资料内问题和 10 个资料外问题测试集，记录检索命中、
回答是否正确、原文是否支持结论、引用是否定位正确，分别报告。
结果未达到目标时修复具体环节，不通过改宽验收标准隐藏问题。

验收：真实“上传 → 问答 → 点击原文”流程成立；
至少给出成功、资料不足、来源已删除三个实际演示。
```

## 14 T10 接通笔记和练习流程

```text
任务 T10：完成学习成果的真实持久化。

笔记写入数据库，保存正文、来源和 revision，处理自动保存失败与冲突。
题目生成采用结构校验，检查题型、选项、答案、解释和引用。
提交前不返回正确答案；评分在服务端完成；提交请求支持幂等。
保存题目版本、用户作答和评分，错题筛选使用真实记录。
知识库删除后，历史笔记正文仍能查看，来源不可用时明确提示。

从新的测试账号开始走完整教材流程，关闭浏览器后重新进入验证。

验收：问答、出题、提交、保存笔记、导出和历史恢复全部使用真实服务；
Mock 退出正式流程；评分和版本冲突有实际检查证据。
```

## 15 T11 让另一位 AI 独立检查

```text
任务 T11：独立审查当前实现，先不要重写架构或大面积改代码。

阅读计划、API、任务记录和实际源码，运行允许执行的检查。
按实现手册 E01 至 E16 和三种视口检查。
优先寻找：无法完成的用户操作、假成功、跨用户访问、答案或密钥泄露、
消息重复、SSE 永不结束、取消失效、数据丢失、错误引用、恢复失败。
视觉问题必须根据参考截图指出位置和差异，不凭个人喜好重设计。

每个问题提供：严重程度、文件或页面、触发条件、复现步骤、
预期与实际、影响、最小修改建议。
区分已确认问题和待验证风险；没有运行过的检查明确写未运行。
输出 docs/QA_REPORT.md，并更新任务清单。

验收：问题可以复现，修复者能直接按步骤操作；
报告不把“构建成功”当成整个产品已验收。
```

将报告中的问题再拆成独立修复任务。每次只修相关问题并复验，不让“修复按钮”变成重写整站。

## 16 T12 部署和交付

```text
任务 T12：建立可恢复的测试部署，然后准备小范围试用。

依据部署环境编写 Docker 配置、反向代理、迁移、环境示例和 README。
测试数据库、文件持久卷、Worker 和 Redis 重启后的状态。
经 HTTPS 域名验证流式响应没有被代理缓冲。
准备备份并实际恢复到隔离实例，检查用户、文件、消息、题目和笔记。
记录构建版本、密钥配置位置、成本统计方法、日常检查和回滚步骤。
正式环境只启用已通过验收的功能。

交付运行地址、版本、测试记录、部署说明、备份恢复证据和已知限制。
涉及公开发布或真实账号配置时，依当前环境授权执行；
需要负责人确认的最终操作，先准备可检查的完整结果。

验收：其他执行者可以照文档部署；重启不丢数据；可备份恢复；
模型失败与配额限制有明确反馈；正式环境无测试密钥与隐式 Mock。
```

## 18 常见偏差的纠正提示词

```text
页面不像参考：请对照固定视口的参考截图，先列出侧栏宽度、
内容宽度、输入框位置、留白、字号、颜色和选中态的具体差异。
只修正这些差异，保留现有功能与组件，不重新设计产品。
```

```text
功能只有外观：请沿用户点击路径检查每个按钮是否有实际行为，
覆盖成功、失败、空态、加载和恢复。指出哪些使用 Mock。
按原契约补全本任务的行为，不添加新模块。
```

```text
两个 AI 的代码无法集成：请先比较公共类型、路由、API、状态和依赖。
以 docs/DECISIONS.md 和当前契约为准，列出最小修复顺序。
先修一个最小流程并验证，再继续其他模块，不整体推倒重写。
```

```text
上下文太长或准备换 AI：暂停新增功能。根据真实源码和实际验证，
更新 HANDOFF 和 TASKS，标明已完成、演示、未接入、失败以及下一步。
输出一个新 AI 可以直接继续的交接包，不能把计划当成已实现结果。
```
