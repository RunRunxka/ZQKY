# 工程架构

## 当前结构

根目录是npm workspace和本地Git边界，仅纳入 `apps/web`。原规划材料和冻结旧版用于追溯，不参与正式依赖解析或运行。

正式前端使用Next.js App Router。根布局提供全局主题；根页面跳转 `/lesson-plans`。教案页面加载客户端 `LessonPlanWorkspace`，但模块加载过程不读取浏览器状态，服务端预渲染首先展示恢复状态。

`WorkspaceShell` 提供项目标识、全局导航、标题和操作插槽。它依赖公共NavigationItem和Next路由，不导入教案数据。未开发入口统一显示“规划中”；未知路径返回404。

## 教案数据流

```text
页面 → LessonPlanProvider（每个编辑器创建独立store）
     → DraftRepository.load → 恢复草稿 → 开放编辑
     → 表单修改store → 即时预览
                   → 600ms防抖 → 串行DraftRepository.save
     → FillProvider.parse → 建议和警告 → 用户确认 → store
     → Word模板映射 / 命名A4打印页面
```

写入器合并尚未发出的版本，异步保存按序执行；失败保留待写版本。导航前等待flush成功，卸载和pagehide也尝试刷新。浏览器关闭时，异步后台写入不具备必达保证，因此未完成保存会触发离开提示。当前默认本地存储写入是同步的。

草稿读取失败不会写入初始示例覆盖坏数据。用户可以备份当前内容后明确替换旧草稿。单机草稿仍是一份文档；跨标签页冲突、多账号、多教案不在当前实现范围。

## 扩展方式

1. 在统一导航和ROUTES文档登记入口及状态。
2. 在 `features/<module>` 实现业务，在 `app` 建薄页面入口；复用公共壳和控件。
3. 模块专有类型留在模块，跨模块契约进入 `contracts`。页面通过明确服务接口读写，避免直接调用模型或数据库。
4. 真正实现时才将导航 `available` 改为true；保留空、错、加载、取消及恢复状态。
5. 新增后端时遵循apps/api规划，不在前端创建假接口或隐式回退演示实现。

## 样式与测试

公共主题在globals.css；教案CSS限定 `.lesson-workspace`。教案打印采用命名 `@page lesson-plan`，只有教案存在时才应用纸张和隐藏规则。切换到其他路由后残留CSS不会触发教案打印布局。

单元测试与纯服务相邻；浏览器回归使用根 `tests/e2e`、固定JSON数据与5174生产服务。浏览器上下文隔离，绝不操作用户现有页面或依赖Vite源码模块地址。

## 2026-09-06 新对话发送静默失败排查与首页调整（已实施，用户指定）

- 现象与根因：新建对话后发送有概率“无反应/无回复”。排查确认两条静默失败路径：①默认问答模型（`defaultChatProfileId`）指向的连接凭证失效（凭证只存后端进程，重启即失效的既定决策）时 `selection=null`，`submit()` 静默返回——Enter 发送毫无反馈，而旧会话若显式选过可用模型则正常，故表现为“新对话才有概率失败”；②页面刚加载 `ready=false` 时 `send()` 也静默丢弃。
- 修复原则：**不做静默模型回退**（沿用“不静默改用其他供应商”决策）；改为消除静默——`send` 在未就绪时等待初始化（memoized，不改变已就绪时的同步语义）；发送被阻止时在输入框旁即时显示原因（缺凭证/未选模型/读取中）并附“打开设置”入口，草稿保留。
- 已实测：默认模型有效时“新建对话→立即发送”压测 10/10 成功；默认模型缺凭证时 Enter 显示“当前模型缺少凭证，请到设置补充后重试。”且草稿保留。
- 首页调整：根路径 `/` 默认跳转由 `/lesson-plans` 改为 `/chat`（用户指定）；教案工作台仍从导航与品牌按钮直达。
- EMPTY_RESPONSE 增强（用户报告“模型未返回正文”后）：三个适配器识别推理输出形态（DeepSeek `reasoning_content`、Anthropic thinking、Responses 推理摘要），推理增量经 `reasoning.delta` 事件透传并在前端折叠展示；流干净结束但零正文时按结束原因给出可操作诊断（推理耗尽预算→提示增大输出上限），正文兼容分块形态；**不做静默模型回退**。

## 2026-09-07 复刻阶段：ask_user 同轮续答语义（已实施）

- 追问（ask_user）采用原版语义：当前轮生成→提问→暂停→接受回答→继续当前轮；同一 sessionId/turnId/助手消息保持关联，禁止以普通 send 另开一轮，也不重新打开已终结轮次。旧交接中"提交后以新轮次继续"的描述作废。
- `ChatService.submitReply` 为可选能力：模拟实现以挂起点保持轮次活动并在提交后同轮续写（submissionId 幂等）；真实服务显式返回 REPLY_NOT_SUPPORTED，不静默转模拟、不把追问字段发给真实后端。

- 未回答题目按原版语义在提交时标记为跳过，不加"必须答完"拦截；提交失败为卡片级失败，保留草稿与选项。

## 2026-09-07 复刻阶段：聊天扩展快照与模拟边界（已实施）

拟定后端开发端口 127.0.0.1:8000，测试端口 8001；前端仍为 5173，浏览器回归为 5174。经 Next 的同源代理转发 `/api/v1` 到 FastAPI；Next 只代理，不实现另一套业务 Route Handlers。实施时验证 POST 流式响应没有被代理缓冲。

后端阶段可新增 `dev:api`、`dev:all`、`test:api` 等根脚本，同时保持现有 `dev/build/start/typecheck/lint/test:unit/test:e2e` 语义。新增命令只有实际可运行后才写入 README 的启动步骤。

## 6. 不接数据库时的数据与接口方案

### 6.1 数据存储分工

| 数据 | 本期实现 | 未来替换方式 |
| --- | --- | --- |
| 原教案草稿 | 保留现有 localStorage 与键名 | 经 DraftRepository 接服务端文档库 |
| 试卷/小练、题目内容、模板文件 | 浏览器 IndexedDB，支持多文档和二进制文件 | PaperRepository / TemplateRepository 替换为 HTTP |
| 对话历史 | 浏览器 IndexedDB；服务端不承诺历史持久化 | ConversationRepository 替换为服务端存储 |
| 模型非敏感配置 | 后端本地 JSON，原子写入、版本检查 | ModelProfileRepository 替换为数据库 |
| API 密钥 | 服务端凭证存储，浏览器只写入、不读回明文 | SecretStore 替换为部署环境密钥管理 |
| 导出任务和文件 | 后端本地文件，任务元数据持久化、有限并发 | 队列、对象存储和任务数据库 |
| 教材与正式题库 | 不建立实际存储 | 本期只定义接口与 unavailable 实现 |

IndexedDB 是浏览器本地存储，不是本次部署题库/教材数据库。UI 应明确“保存在当前浏览器”；缓存清理前需要 JSON 备份。不要把上传模板二进制塞进 localStorage。

接口选择应允许异步实现，即使目前只读写本地。只有成功写入后才显示“已保存”；保存失败保留待写状态。多个标签页通过 revision 检查/通知避免静默覆盖；用户导入 JSON 前必须验证版本和结构，创建新文档或明确确认替换。

### 6.2 公共实体最小字段

新建实体建议统一拥有 `id、schemaVersion、revision、createdAt、updatedAt`。文档 ID 由应用生成稳定 UUID；revision 在当前存储实现内用于冲突检测，不作为权限依据。

- PaperDocument：试卷内容、纸张配置、模板 ID/版本、来源快照。
- Conversation：标题、消息、模型配置 ID、创建时间、最后修改时间。
- ModelProfile：供应商连接 ID、模型 ID、协议、能力、生成参数，不含返回给前端的密钥。
- TemplateRecord：用途、原文件引用/哈希、字段映射、支持报告、版本。
- ExportJob：文档 revision、模板版本、状态、产物、错误、过期时间。

当前服务端只有本机单用户空间，明确固定作用域 `local`；不信任浏览器传入的 owner 字段。未来引入账号后，作用域由认证上下文提供，再迁移本地数据。

### 6.3 凭证与本地服务

最小可用方式可通过服务端环境变量引用 API Key；模型设置最终应支持录入凭证且不会回显明文。需要“记住密钥”时，使用独立加密凭证文件，主密钥来自环境或操作系统凭证设施，不与密文一起硬编码。

未完成安全持久化时只能提供明确的“当前服务进程内使用”选项，不悄悄落盘明文。日志、备份 JSON、报错和模型返回对象均不包含凭证。

仅监听 loopback；服务端验证允许来源、请求类型及必要的本机会话保护。自定义 API 地址限制协议，校验跳转，不能允许读取任意本地文件或将服务变成开放代理；本地模型地址应通过显式配置允许。本期服务不能直接当成公网多用户部署方案。

### 6.4 未来双库接口

建议先定义以下业务接口（名称是拟定契约，不是当前源码）：

```text
TextbookRepository.list / get / listChapters
TextbookRetriever.search / getSource
QuestionRepository.search / getByIds
QuestionSelector.select
PaperRepository.list / load / save / delete
TemplateRepository.list / load / save
ConversationRepository.list / load / save / delete
ModelProfileRepository.list / load / save
SecretStore.put / resolve / delete
DocumentRenderer.render
```

教材/题库不可用实现返回明确的能力不可用错误，不能返回空列表冒充“库中没有资料”。生产页面不请求规划接口；只有用户主动进入能力时显示说明。固定示例数据仅可存在于测试或显式“载入示例”中，不自动当作用户的题库。

## 7. 学习问答与模型调用

### 7.1 首期功能清单

新建会话、历史列表、重命名、删除确认、模型选择、发送文本、流式回复、停止生成、失败重试、复制答案和本地历史恢复。模型切换不删除会话，历史消息标注实际使用的模型。

本期不做 RAG、任意附件解析、联网搜索、执行代码或 MCP 调用。选择教材、调用技能等只显示规划提示。聊天不能声称“已阅读教材库”或“已从题库选题”。

上下文要有上限：保留完整本地历史，发送时按模型上下文预算选取消息；截断策略必须可解释，不能无限发送全部历史。失败重试不重复追加同一条用户消息，停止后的部分回复明确标注“已停止”。

### 7.2 模型配置表单

连接字段：显示名称、协议、Base URL、认证方式/凭证、必要的允许请求头。模型字段：实际模型 ID、上下文长度、输出上限、温度等支持参数、能力标记。

模型列表自动发现只是可选便利功能；不支持 `/models` 的供应商仍可手动输入模型 ID。能力值区分“已验证 / 人工声明 / 未知”，不可仅由模型名字判断。

优先实现并测试：

1. OpenAI-compatible Chat Completions。
2. Responses 协议适配（按接口支持情况选择，不能仅替换 URL）。
3. Anthropic Messages 协议适配。

Gemini 原生及其他协议作为后续适配任务；经兼容接口使用时明确协议限制。不将“可自定义地址”宣传为“兼容所有模型”。

### 7.3 统一模型接口

后端 Provider 接收标准消息、生成参数、可选工具定义与取消信号；输出标准文本事件、工具请求、结束原因和用量。供应商特有内容留在适配器内部，不让前端解析多套 SDK 响应。

工具调用和结构化输出字段本期预留，不执行外部工具。若模型意外返回 tool call 且没有可执行工具，明确结束为不支持状态，不把工具 JSON 当普通答案，也不运行任意函数。

厂商参数需要按能力过滤：不支持 temperature、system、某种 token 参数、图像或 JSON Schema 时，应在发送前校验或按协议转换。响应中的未知 finish reason、空内容和截断都应规范化处理。

供应商工厂只加载所选协议；连接池有明确关闭生命周期。每次请求携带自己的配置，不在全局保存对话、用户密钥或可变消息列表。

### 7.4 流式、取消与异常

推荐使用 `fetch + ReadableStream` 消费 POST 返回的 SSE；原生 EventSource 不支持此 POST 请求体。必须正确处理 UTF-8 跨块字符、SSE 多行和供应商事件边界。

客户端用 AbortController 停止；后端取消上游流并释放连接。断线后保留已收到内容，不自动重发可能收费的请求。断线恢复首期允许“明确失败 + 用户重试”，不伪称支持断点续传。

401/403 显示认证错误，429 显示限流，超时和网络错误分开。流开始前使用 HTTP 错误；流开始后发送标准 error 事件。限量自动重试只适用于可判定安全的瞬时错误，输出已经开始或请求结果不确定时不静默重试，不自动换供应商。

### 7.5 最小真实验收

至少使用一个用户授权的真实连接完成发送、中文流式、停止、重新发送；密钥缺失时可做协议模拟测试，但必须把“真实连接验收”标为未执行。模拟服务器仅用于测试，不出现在生产错误回退中。

多个协议的实现需要各自协议测试；没有某家真实凭证时不宣称该家真实调用已验收。连接测试消耗可能的真实额度，UI 应明确这是一次小额实际请求。

## 8. 智能组卷工作台

### 8.1 两种用途与纸张预设

| 用途 | 默认纸张 | 默认方向与布局 | 可调整项 |
| --- | --- | --- | --- |
| 正式试卷 | A3 | 横向，双栏预设 | 方向、分栏、页边距、密封/装订区、字号 |
| 课堂小练 | A4 | 纵向，单栏预设 | 方向、分栏、页边距、字号、答题留白 |

A3 为 297×420 mm（横向 420×297 mm）；A4 为 210×297 mm（横向 297×210 mm）。纸张设置保存到每份文档中。用途只是默认配置，不限制用户将小练切到 A3 或试卷切到 A4。

从 A3 切到 A4 必须重新分页，保持题目、分值、顺序和手动设置的业务内容；不能只缩放成一张截图。自动重新排版与用户插入的分页符需采用明确规则，切换有冲突时提示并可撤销。

双栏、双面打印、小册子拼版是不同能力。本期要求 A3/A4 与栏布局；双面装订顺序和小册子拼版规划中，不伪造打印机控制能力。

### 8.2 无正式题库时的题目来源

首期支持手动录入、JSON 结构化导入和用户主动载入示例。普通 DOCX 题目文件自动拆题、扫描试卷识别、教材生成题和从题库选题均留为规划能力。

必须区分“导入试卷模板 DOCX”和“导入题目内容”。上传一个 Word 模板不会自动获得题目，也不能将整份试卷转图片后称作可编辑题库。

### 8.3 试卷最小数据模型

```text
PaperDocument
  id / schemaVersion / revision / createdAt / updatedAt
  title / subtitle / subject / grade / durationMinutes
  purpose: exam | practice
  pageSettings: size / orientation / columns / marginsMm / font / fontSize
  headerFooter / bindingArea / studentInfoFields
  templateRef: id + version
  sections[]
    id / title / instructions
    questions[]
      instanceId / sourceQuestionId? / sourceVersion? / sourceKind
      type / stemBlocks / options[] / answerBlocks / analysisBlocks
      subQuestions[] / score / answerSpace / locked
  assets[] / sourceSnapshots[]
```

`sourceKind` 区分 manual、import、example、future-bank、future-ai。每次插入题目有独立 instanceId；题库 ID 不能替代试卷内实例 ID。组卷保存题目快照，未来题库改题不影响已保存试卷。

文本、列表、表格、图片、公式采用明确内容块，不能全部拼接为一段 HTML。首版明确支持子集和导入检查；不支持的块必须拒绝或提示，禁止静默丢弃。

### 8.4 必须完成的编辑能力

- 新建试卷/小练、修改标题与学生信息、保存、重开、另存副本、删除确认。
- 新增/删除/排序大题和题目；至少支持选择、填空、判断、简答，以及组合题数据结构。
- 修改分值、自动统计总分；空分值、负数和总分不一致能定位到具体题。
- 配置答题区域、题号和大题说明；选项顺序变化时同步答案引用，不能仅交换显示文字。
- 撤销重做，包含排序、删除和纸张切换；保存不清空撤销栈，重开后的历史恢复范围明确说明。
- JSON 导入、导出备份；非法版本、损坏文件、重复 ID、丢失附件时不覆盖当前文档。
- 学生卷与教师卷分别导出；学生卷产物中不嵌入答案/解析内容，而不只是用 CSS 隐藏。

### 8.5 实时预览要求

右侧为分页纸张，显示纸型、页数、当前缩放、溢出或未完成渲染状态。编辑即更新轻量预览，连续输入时防抖，不能每输入一个字都启动 Word 转换。

题干尽量与选项保持在一起；大题标题不能孤立在页底；超长题允许按可解释的规则跨页，不裁切内容。公式、图片和表格按可用栏宽排版。

切换纸张、栏数、字体、学生卷/教师卷模式后重新分页。文档为空、特别长、题目带图和同一题超过一栏高度均有验收样例。

### 8.6 未来自动选题边界

预留条件：学科、年级、教材版本、章节、知识点、题型数量、总分、难度目标、排除/锁定题目。QuestionSelector 返回选中题目 ID/版本、覆盖摘要和未满足条件。

数量、分值、必选/排除是可验证规则；模型只理解需求或辅助解释，不能代替规则求解。候选不足时报告缺口；AI 新题进入待审核，不能自动当作已审核题库题使用。

## 9. DOCX 模板、预览与导出

### 9.1 模板处理流程

上传 DOCX → 保存原件及哈希 → 结构与安全检查 → 字段识别/手动映射 → 测试数据填充 → 预览 → 保存模板版本。

模板支持分级：

1. **受支持模板**：指定占位符、文本/表格区域、受支持的图片/公式与重复题目块；能够完成全部验收。
2. **需映射模板**：普通学校 DOCX，经用户指定填充字段、重复区域和固定区域后试填；不能假设自动识别一定正确。
3. **暂不支持模板**：复杂文本框、嵌套/浮动结构等超出实现范围；给出问题位置、原因和修改建议。

首期支持 DOCX 上传和受控字段映射，不承诺任意 Word 文件都能自动无损转为模板。AI 自动识别字段作为后续增强；它的建议也要经过模板预览验证。

### 9.2 教案与试卷共用部分

共用模板元数据、上传检查、文件存储适配、版本、字段映射 UI、渲染任务及下载。教案与试卷各自保留内容 Schema 和填充器，不用试卷字段替换 LessonPlanData。

原教案模板作为 legacy 内置模板继续可用，不覆盖原文件；先在组卷验证通用模板流程，再以新增适配器接入教案。模板变化只影响新版本，旧文档继续绑定原模板版本。

模板纸张尺寸与当前 A3/A4 配置冲突时明确提示：使用模板页面设置，或生成适配副本并重新验收。不能显示 A4 实际导出 A3，也不能把旧教案特殊尺寸静默改为 A4。

### 9.3 双层预览与最终产物

- **实时编辑预览**：HTML/CSS 内容块渲染，目标是编辑响应及时；可以提示“编辑预览”。
- **正式分页预览**：将指定文档版本填充为 DOCX，再转换为 PDF，在右侧显示；标注对应版本。
- **PDF 下载**：直接下载正式预览使用的同一份 PDF，而不是另走浏览器打印生成不同版式。
- **Word 下载**：下载该次填充后的 DOCX；在不同 Word/WPS 中可能重新分页，必须保留人工版式验收。

模板上传和本地编辑不依赖数据库。正式渲染可以依赖本机后端与转换程序；后端停止时仍能编辑和备份，但正式导出按钮说明服务不可用。已存在的教案浏览器打印功能保留，不能未经迁移验收就删除。

### 9.4 渲染实现约束

先验证现有 docxtemplater 能复用的范围；复杂表格循环、图片、公式等能力可能需要补充实现或其他工具，不能假定已安装的核心包包含所有扩展。选择依赖前核对许可证，不默认引入收费模块。

候选转换路线为受控 DOCX 填充 + LibreOffice PDF 转换。固定字体和转换版本，独立任务目录/用户配置目录，避免多个进程争用同一个 Office 配置。转换器不可用时明确失败，不输出空白占位 PDF。

每个任务包含 inputHash、documentRevision、templateVersion、renderOptions、rendererVersion。较早任务完成后不得覆盖较新内容；旧预览必须显示“内容已更新，需要重新渲染”。重复点击相同导出请求复用任务或按幂等键处理。

导出任务并发受限，设置超时和取消。后端重启时将未完成任务标为中断，不永久显示处理中。临时文件按任务清理，用户原件和已确认下载文件不混在临时目录。

上传检查扩展名、ZIP/OOXML 结构、大小、解压后大小、路径和外部关系。忽略或拒绝宏、外部自动加载和不支持对象，不执行上传内容中的脚本。文档转换作为受限子进程运行，不提供任意 shell 指令接口。

## 10. 后续 RAG、双库与 Agent 扩展

本节是预留契约，不属于当前实现清单。现在不安装服务、不建立索引、不执行真实外部工具。

### 10.1 教材资料库

实体：教材、教材版本、章节、文件、解析任务、原文块、图片/表格/公式、索引版本。来源定位使用 PDF 页码/区域或 DOCX 段落/表格位置；DOCX 页码必须对应明确的渲染版本。

检索输入包含教材、版本、章节范围和查询；输出包含来源 ID、原文、定位和相关度。权限过滤应在检索前生效。以后删除资料、重新解析或更换嵌入模型需同步处理索引版本，不能返回陈旧来源。

### 10.2 题库

实体：题目、版本、题组、子题、答案、解析、媒体资源、知识点、审核状态、来源。和试卷内临时题目分开，后者以后可通过明确操作入库。

QuestionRepository.search 返回分页结果、筛选条件及稳定题目版本；getByIds 精确取题。题库缺失、查询无结果和权限不足是不同错误。难度区分人工标注、模型估计与实际统计。

### 10.3 教材自动生成教案

未来路径：选择教材/章节 → 明确课时与学情 → 检索原文 → 制定教学结构 → 生成结构化建议 → 校验 → 用户确认进入教案。

通过新增服务把资料引用与生成建议接入现有 FillProvider/教案文档模型；需要新字段时设计版本迁移。现有纯文本输入不能假装已经携带教材全文或来源。

### 10.4 Agent 与工具

拟定 AgentRun：id、taskType、status、steps、modelProfileId、budget、artifacts、error。状态包括 queued/running/waiting_for_user/succeeded/failed/cancelled/interrupted。

先规划少量业务工具：search_textbook、search_questions、validate_paper、propose_lesson_patch、render_document。工具调用由服务层校验作用域、输入和副作用，不让模型直接执行 SQL 或写文件路径。

### 10.5 MCP 和 Skills

MCP 负责对外部工具/资源建立受控连接；Skills 负责定义教学任务步骤、输入输出、模板和允许工具。它们通过统一工具注册表接入 Agent，不直接绕过业务服务。

预留连接/技能的 ID、版本、启用状态、能力、超时和权限说明。MCP 密钥在服务端；Skills 的脚本执行需要额外隔离。用户上传教材、模型返回和外部工具内容都是资料，不能自动覆盖系统规则。

产品 Skills 与开发机器上的 Codex Skills 分开管理。本期不要扫描并自动装载开发者 `.codex/skills`，不要把电脑上的全部 MCP 连接搬进产品。

## 11. 接口契约与错误规范

### 11.1 状态和单一来源

当前 `docs/API.md` 记录现有接口，以下是新增草案。服务实现时先更新 OpenAPI/Schema，再生成或核对前端 DTO。没有后端实现前不能声称类型已经由 OpenAPI 生成。

前端用静态模块登记保证离线仍能展示导航；后端 `/capabilities` 报告真实运行能力。请求失败显示“服务不可用”，不把未知能力推断为已连接。

### 11.2 本期拟实现 HTTP 接口

| 方法与路径 | 用途 | 实施阶段 |
| --- | --- | --- |
| GET `/api/v1/health` | 精简后端可用性，不返回敏感配置 | D02 |
| GET `/api/v1/capabilities` | 模型、模板渲染等能力状态；RAG/题库/MCP/Skills 为 planned | D02，随功能更新 |
| GET/POST `/api/v1/model-connections` | 列出/创建供应商连接 | D03 |
| PUT/DELETE `/api/v1/model-connections/{id}` | 更新/删除；密钥只写入，返回脱敏状态 | D03 |
| GET/POST `/api/v1/model-profiles` | 模型及用途配置 | D03 |
| PUT/DELETE `/api/v1/model-profiles/{id}` | 修改模型配置和能力声明 | D03 |
| POST `/api/v1/model-profiles/{id}/test` | 小请求测试实际能力 | D03 |
| POST `/api/v1/chat/stream` | 规范化 SSE 对话，服务端取消上游 | D04 |
| POST `/api/v1/templates/inspect` | 上传检查、支持报告、返回受控临时上传 ID | D05–D07 |
| POST `/api/v1/exports` | 按文档快照、模板、纸张创建渲染任务 | D07 |
| GET `/api/v1/exports/{id}` | 状态、文档版本、错误和产物信息 | D07 |
| POST `/api/v1/exports/{id}/cancel` | 取消未完成转换 | D07 |
| GET `/api/v1/exports/{id}/artifacts/{format}` | 受控下载 docx/pdf；检查作用域和有效期 | D07 |

浏览器保存模板记录；inspect 返回的上传 ID 有明确期限。渲染时可携带有效上传 ID；过期后从 IndexedDB 重新上传，不把临时 ID 当永久模板存储。

### 11.3 仅设计、不挂载成功路由的接口

教材列表/上传/章节/检索、正式题库增删查、题库自动组卷、RAG 问答、AgentRun、MCP 和 Skills 管理均仅预留业务契约。路由命名在实施时登记；本期不创建返回200与示例内容的假后台。

若确需挂载占位路由，返回501及 `FEATURE_NOT_IMPLEMENTED`，前端不得自动调用。生产 UI 中“规划中”不等于用失败请求来检测功能。

### 11.4 聊天事件和请求草案

请求包含 requestId、modelProfileId、messages、受限生成参数；conversationId 仅用于本地关联，服务端不能据此认定具有访问某个用户数据的权限。

事件建议：

```text
message.start  {requestId, messageId, modelProfileId}
text.delta     {messageId, text}
usage          {messageId, inputTokens?, outputTokens?}
message.end    {messageId, finishReason}
error          {requestId, code, message, retryable}
```

未来新增 tool.start/tool.end/artifact/citation 等事件须版本化，前端遇到未知事件不崩溃。用量缺失显示未知，不能当成零费用。

### 11.5 通用错误与版本冲突

错误统一 `code、message、requestId、retryable、details?`，details 只能包含脱敏且适合前端展示的内容。

建议错误：MODEL_NOT_CONFIGURED、UNSUPPORTED_PROTOCOL、UPSTREAM_AUTH_FAILED、RATE_LIMITED、CONTEXT_TOO_LARGE、UPSTREAM_TIMEOUT、FEATURE_NOT_IMPLEMENTED、TEMPLATE_UNSUPPORTED、RENDER_FAILED、REVISION_CONFLICT。

存储保存接收 expectedRevision，冲突返回409或等价本地异常；不能以“最后保存者覆盖”为默认行为。所有导出绑定输入版本，下载前核对当前文档是否已变化。
