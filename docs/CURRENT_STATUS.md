## 问题 2 + 4a/4b：删除语义重做（本次，2026-10-13）

用户裁定：**舍弃所有归档功能，只留删除** + **拆开交叉引用**。实现分两侧：

### 后端（合同与级联清单见 [API.md](API.md) 的「删除语义」小节）
- **学生删除冻结契约**：`DELETE /students/{id}?expectedRevision=N` → 200 `{mode, message}`；
  两种模式**班级 studentCount 都下降**——`deleted`（无参测引用：归属行+学生行物理删除、
  名单导入匹配指针置空）/ `removed_with_history`（有参测快照引用：关闭活跃归属 + 身份标记已移除，
  成绩证据保留）。**根因修复**：人数统计改为「活跃归属 ∧ 学生身份活跃」，与班级学生列表同口径
  （历史脏数据不再顶高人数，且不改用户数据）。
- **拆开交叉引用**：班级（归属/名单批次/无参测人次的参测范围级联；成绩链证据与教案 → 409 逐项列出）、
  试卷（修订链含已确认随卷级联；被施测引用 → 409 引导先删施测）、学情报告（派生练习连带历史级联、
  教案来源指针置空；教案冻结生成血缘 → 409）、施测（**级联自有成绩链**：人次/导入/修订/小题分/
  报告/派生练习/转换/成绩模板导出，唯一 409 = 教案冻结血缘）。
- **成绩链保护策略（调研结论）**：成绩链所有者是施测；删除施测 = 删除这条链（唯一显式销毁入口），
  其它实体的删除永不静默销毁学生成绩（级联/置空/409 分流）。所有级联单事务完成，不可变兜底触发器
  按 `sqlite_master` 原文摘除、末尾逐字恢复（`app/repositories/teaching/triggers.py`）。
