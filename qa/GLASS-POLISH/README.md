# GLASS-POLISH v1 批次证据

批次：**玻璃主题三处调整**，2026-09-23。用户提出的三条诉求与对应根因：

| # | 用户原话 | 实测根因 |
| --- | --- | --- |
| 1 | 浅色主题流动颜色太浅，加深一点 | 浅色 palette 的底色取 `hsl(h, 0.25, 0.955)`（近白），而流体用 `lighter` **加法**叠加——底色越白越快饱和成纯白。改前画布平均亮度 **246.4**、平均 RGB (243,247,250)，基本就是白 |
| 2 | 浅色要像深色一样覆盖右侧聊天输入界面 | `chat.css` 给 `.chat-main` 与 `.chat-composer` 硬编码了 `background: white`；深色方案在 `glass.css` 里显式置了透明/玻璃（`:261`），**浅色这一路从来没补齐** |
| 3 | 流动效果不明显，稍微增强一点 | 光斑漂移幅度偏小（ax 0.14 / ay 0.08 量级），而实测静置时帧间变化有限 |

## 1. 改了什么

- `components/layout/fluid-tones.ts`：**只改浅色分支**（深色分支一字未动）。
  - `color1` 0.95 饱和 / 亮度 `ramp(0.26, 0.46, 0.8)`（原 `ramp(0.3, 0.52, 0.9)`）
  - `color2` 饱和 0.78 + 亮度斜坡（原固定 0.55 / 0.86）
  - `color3` 底色 `ramp(0.855, 0.9, 0.95)`（原固定 0.955）——**给加法留出余量是关键**
- `components/layout/fluid-shader.ts`：光斑漂移幅度 ax/ay 约 **×1.4**（位置与周期不变，只放大位移）；光斑叠加不透明度 `0.38 → 0.42`。
- `styles/glass.css`：新增浅色「主区与输入区让位」块——`.chat-main` 透明、`.chat-composer` 玻璃（`rgba(255,255,255, calc(0.3 + var(--glass-alpha) * 0.5))` + `blur(var(--glass-blur))`）、焦点描边、以及把 6px 白色渐隐条改为半透明（否则会在透明主区上留一道白边）。

## 3. 流动强度（`fluid-motion.cjs`，同页采样间隔 2.5s）

| 主题 | 平均像素变化 | 变化 >2 的像素占比 | 单点最大变化 |
| --- | --- | --- | --- |
| 浅色 | 2.13 / 255 | 35.9% | 11.7 |
| 深色 | 3.14 / 255 | 38.1% | 17.7 |

即流体确实在持续运动（不是静态画面）。**「增强」幅度**由代码可核：漂移幅度 ×1.4、不透明度 0.38→0.42；
上表的亮度标准差与色调数增长是同一变化在画面上的体现。**未做**改动前的运动基线采样（需回退构建两次），
因此"增强前 vs 增强后"的运动差值没有实测数字——需要更准的对比可以补做。

## 6. 未做 / 已知事项

- **玻璃主题没有任何自动化测试覆盖**：全仓搜索确认没有测试开启 `data-glass`。
  这也是前述"预检 bug"和这三处观感问题能长期存在的原因。若要让视觉不再回退，需要补一组带 `data-glass=on` 的
  浏览器基线（现有 e2e 全部跑在非玻璃主题下）。
- 会话态（有消息时）未在浏览器里跑：本机后端未启动，起不了真实会话。渐隐条规则用临时插入同名元素验证了命中，
  未做整页会话态截图。
- 未改**中栏"学习记录"列**：它仍是 `var(--surface)` 实底（与深色一致），因此在浅色下这块灰底与蓝色背景
  对比略突兀。用户本次只要求右侧，故保留；要一并对齐可以再开一小步。
- 未同步 `glass-chat-scaffold` 技能：它的模板里也有这三个文件，且其 `references/baseline/*.png`
  与本调色板绑定——同步会连带需要重出 9 张基线图与更新 manifest 指纹，属于独立一次操作。
